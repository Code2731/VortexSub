# 자막 표시 입력 계약

2026-10-09. `apps/EchoSub.Desktop/CaptionScheduleStore.cs`의 계약이다.
[S1 시뮬레이션](evidence/caption-policy-simulation-windows-20261009.md)의 후속 구현이다.
Desktop과 검사 프로젝트에서 빌드한다. 후보 배정기·오버레이 진단에 연결했다.
MainWindow live 경로는 새 표시기를 사용한다. 모의 표시와 기존 회귀는 별도다. [후보 배정기](CAPTION_SCHEDULED_READER.md)를 읽는다.

## 입력

`CaptionScheduleInput`은 번역 본문과 다음 정보를 담는다.

| 필드 | 규칙 |
| --- | --- |
| `Identity` | product/session/epoch/segment/unit 시작 위치를 구분한다. segment와 session/epoch는 양수다. |
| `SourceRevision`, `RequestId` | 양수다. 같은 단위에서 revision, request 순으로 오래된 결과를 거부한다. |
| `IsFinal` | 전체 최종 번역이다. 시작 위치는 0이다. 수용한 전체 final 뒤 같은 segment의 preview는 거부한다. |
| `SourceSpan` | 원문의 UTF-16 `[Start, End)`와 기준 revision이다. 없는 범위는 미상으로 남긴다. |
| `Target` | 표시 접두어가 없는 번역 본문이다. 빈 본문은 입력 철회가 아니다. |
| `AtSeconds` | 단조 증가하는 UI 수신 시각이다. worker의 음성 관측 시각과 구분한다. 단위는 초다. |

`CaptionScheduleInputs.FromRecord`는 완료·적용 revision이 일치한 번역 기록을 변환한다.
부분 번역은 `TranslationPrefix`의 끝 위치와 `TranslationSource`로 시작 위치를 검증한다.
길이가 맞아도 실제 suffix가 다르면 거부한다. Unicode 문자소의 중간 경계도 거부한다.
번역 원문 단위가 없는 예전 기록은 `SourceSpan = null`이다. 시작 0을 범위 증거로 사용하지 않는다.
이 변환은 기존 `CaptionPresentation`의 원문 안정성 판단을 대체하지 않는다.
연결 단계에서는 표시 대상으로 선택된 번역 기록을 전달해야 한다.

## 상태 분리

- `Latest`: 같은 단위의 최신 입력 하나다. 새 입력이 이전 미표시 입력을 교체한다.
- `Displayed`: 실제 줄 배정 또는 검증된 재사용으로 전달한 번역 범위·본문·원문 범위·revision·request·슬롯·읽기 기한이다.
  미표시 입력을 취소해도 표시 이력의 원문 범위는 유지한다.
  줄 만료 뒤에도 제한된 비교 이력을 보관한다.
- `Comparison`: 교정 여부를 판정할 후보다. 그 자체가 의미 오류의 확정 판정은 아니다.
- `Lease`: 현재 읽기 보호 상태다. 저장 압력으로 삭제하지 않는다.

`Begin`으로 현재 세션을 명시한다. 이전 세션 입력이 새 세션을 자동 시작하지 않는다.
`Stop`과 새 `Begin`은 상태를 초기화한다. 토큰 generation은 초기화하지 않는다.
같은 식별자·revision으로 다시 시작해도 이전 토큰은 무효다.
API는 한 UI 스레드에서 사용한다. 오디오 콜백에서 사용하지 않는다.

## 교체·표시 규칙

`Submit`은 입력을 수용하고 토큰을 반환한다. 같은 버전의 동일 입력은 큐 기한을 갱신하지 않는다.
같은 버전의 다른 본문은 `VersionConflict`다. 취소한 버전의 재전달은 `CancelledVersion`이다.
다른 단위의 최신 번역을 같은 입력으로 합치지 않는다.

`Next`는 현재 작업 또는 다음 작업의 복사된 상태를 반환한다.
`Display`에는 현재 토큰, 실제 배정한 번역 범위와 슬롯을 전달한다.
범위는 현재 표시 진행 위치부터 이어져야 한다. 문자소 중간이나 빠진 범위를 건너뛰지 않는다.
append는 기존 글자를 유지한다. 같은 줄의 이력 조각 하나로 합친다.
읽기 보호는 최소 2.5초다. 새 아랫줄은 현재 윗줄보다 최소 0.25초 뒤에 만료한다.
아랫줄이 보호 중이면 일반 새 내용이나 append를 윗줄에 넣지 않는다.
예외는 같은 원문 범위·revision의 검증된 닫힌 아랫문장을 유지하는 앞문장 교정이다.
윗줄이 이미 만료했고 교정 앞부분 전체가 한 줄에 들어갈 때만 허용한다.
이전 아랫줄은 기존 만료 시각을 유지한다. 새 윗줄에는 새 읽기 시간 2.5초를 준다.

일반 교정 후보는 관련 줄을 읽은 뒤 배정한다. 위 예외는 `Display`에서 증거를 다시 검증한다.
새 교정 버전의 줄은 같은 버전의 다음 줄 배정을 막지 않는다. 이전 버전의 관련 줄만 보호 장벽이다.
같은 원문 범위의 전체 교정이면 같은 segment의 다른 부분 단위도 관련 줄이다.
`Complete`는 현재 입력의 실제 표시 범위가 끝까지 도달했을 때만 성공한다.
원문 겹침·철회의 전체 교정은 이전 단위의 표시 진행 위치를 가져오지 않는다.
문장 LCS의 [재사용 증거 전달](CAPTION_SENTENCE_REUSE.md)을 구현했다.
`Reuse`는 실제 표시 이력을 다시 검증한 범위만 진행한다. 배정·재사용하지 않은 내용은 완료 처리하지 않는다.
재사용 이력은 `Reused = true`, `Slot = -1`이다. 새 줄 배정이나 읽기 기한 갱신이 아니다.
선행 분리자는 `ConsumeSeparator`로 검증해 소비한다. `Separator = true`, `Slot = -1`로 상한 내 이력을 남긴다.
공백이 아닌 글자를 이 경로로 완료 처리하지 못한다. separator append도 일반 글자의 기한을 줄이지 못한다.

## 원문 범위와 무효화

같은 revision의 원문 범위는 교차 여부를 비교할 수 있다.
revision이 다르거나 범위가 없으면 `UnknownSourceRange`다.
원문 위치를 번역 글자 위치로 바꾸지 않는다. 문자열 의미의 동등성도 추측하지 않는다.

알려진 비중첩 단위의 미표시 입력은 보존한다.
전체 final 또는 알려진 중첩 범위는 이전 미표시 suffix 단위를 취소한다.
현재 부분 작업을 전체 final이 대체하면 현재 작업 자리를 인계한다.
이 인계 때문에 다른 발화의 큐를 폐기하지 않는다.

원문 수정의 `Invalidate`는 미표시 입력만 취소한다. 기존 줄과 읽기 기한은 유지한다.
반복 수정은 읽기 기한을 늘리지 않는다.
`withdraw = true`는 최종 실패·폐기 경로다. 해당 표시 줄을 지우고 재진입을 막는다.
worker의 세션 판단과 중지 결정은 기존 경로가 맡는다.

## 저장 상한과 퇴역

| 항목 | 상한 |
| --- | ---: |
| 입력 본문·원문 범위 끝 위치 | 16,384 UTF-16 단위 |
| 저장한 최신 본문 + 표시 이력 본문 | 131,072 UTF-16 단위 |
| 추적 단위 | 64개 |
| 대기 단위 | 4개 + 표시를 시작한 현재 작업 1개 |
| 표시 이력 조각 | 전체 256개 / 단위별 64개 |
| 대기 시간 | 10초 |
| product/session 문자열 | 128 UTF-16 단위 |

본문 예산은 문자열 payload다. 객체·메타데이터·반환한 복사본의 메모리는 포함하지 않는다.
메타데이터 개수도 위 상한으로 제한한다. 비교 후보는 최신 입력을 참조하며 본문을 별도 복사하지 않는다.

입력 저장 전에 큐 교체·문자 예산·퇴역을 예약 검사한다.
수용할 수 없으면 `StorageCapacity`를 반환한다. 기존 미표시 입력과 읽기 보호를 유지한다.
새 입력의 실패로 먼저 다른 발화를 지우지 않는다.
유효한 시각에 도달한 줄 만료와 대기 만료는 별도 처리다.

읽기를 마치고 미표시 작업이 없는 가장 오래된 segment부터 전체 그룹을 퇴역한다.
살아 있는 앞 segment를 건너뛰어 퇴역 watermark를 올리지 않는다.
같은 segment의 일부 단위만 퇴역시키지 않는다.
퇴역 입력은 `Retired`, 더 새 segment가 표시된 뒤의 늦은 입력은 `LateUnit`이다.

조각 상한이나 문자 예산에는 읽기를 마친 이력만 줄일 수 있다.
이 경우 `HistoryComplete = false`와 `HistoryTrimmed`를 기록한다.
이력이 불완전하면 이후 LCS가 전체 대응을 입증했다고 처리하지 않는다.
`QueueCapacity`, `QueueAge`와 저장 거부를 구분한다.
오버레이 폐기를 실제 번역 기록의 삭제로 해석하지 않는다. 최종 기록은 기존 `WorkerHistory`가 보관한다.
알림에는 본문을 넣지 않는다. 사유별 누적 카운터는 포화 증가한다.
