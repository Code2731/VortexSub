# 리뷰 종합 개선 계획

2026-10-03. 대상은 번역 설정, VAD 계측, 자막 전달과 읽기 정책이다.
사용자가 이 계획을 구현 목표로 승인했다. 전체 번역 고도화 계획은
[기존 계획](TRANSLATION_IMPROVEMENT_PLAN.md)을 따른다.

## 목표

설정 실패 뒤에도 worker를 유지한다. 서로 다른 자막 단위의 표시 순서를 보존한다.
같은 자막 단위의 수정본은 합친다. 대기 상한을 초과하면 사유를 기록한다.
처리 지연과 읽기 대기를 각각 측정한다. 모든 기간은 초로 표시한다.

## 구현과 수용 기준

| ID | 작업 | 수용 기준 |
| --- | --- | --- |
| R1 | 번역 설정 커밋 실패 복구 | 기존 연결·모델·프로필 유지, pending 폐기, 상태 발행, 재시도 성공 |
| R2 | 정정 길이 경계 검증 | 383/384/385바이트와 UTF-8 입력 검증, `RepairTooLong` 뒤 final 번역 진행 |
| R3 | VAD 시각 분리 | 처리 시작·완료·수신 분리, push/poll 구분, 과거 로그의 누락값 유지 |
| R4 | 자막 전달 보존 | 스냅샷 한 번에 도착한 여러 문장 표시, 같은 단위 수정 합치기, 원문 무효화·세션 변경 반영 |
| R5 | 대기 상한과 진단 | 대기 4개·10초, 입력 16,384 UTF-16자, 초과 사유와 첫 줄 대기 기록 |
| R6 | 모델 계약·저장소 정리 | Rust 모델 ID 상수와 다운로드 매니페스트 일치 검사, 프로필 차이 설명, Python 캐시 제외 |
| R7 | 연결·렌더 검증 | 실제 창/IPC/타이머로 연속 문장·중지·재연결 검사, 글자 Run 보존 및 저장 픽셀 검사 |

위 숫자는 초기 정책이다. 읽기 시간은 기존 줄당 2.5초를 유지한다.
정상 부하에서는 문장 누락이 없어야 한다. 지속적인 과부하에서는 지연과
읽기 시간을 함께 보장할 수 없으므로 다음 초과 정책을 적용한다.

## 대기 정책

* 가장 오래된 대기 단위를 용량 초과 시 제거한다: `QueueCapacity`.
* 10초를 넘은 미표시 단위를 제거한다: `QueueAge`.
* 다른 단위가 대기하고 읽기 줄이 비었을 때, 10초를 넘은 현재 단위의
  미표시 꼬리를 제거한다: `UnreadTailAge`. 보이는 줄을 조기 제거하지 않는다.
  2026-10-04 보완: 꼬리가 한 줄에 들어가면 먼저 표시한다. 다음 단위는 빈
  아래 줄에 이어 표시한다. `TailRetained/FitsOneLine`으로 기록한다.
* 표시한 세그먼트보다 늦게 도착한 과거 세그먼트는 `LateUnit`으로 기록한다.
* 입력 길이 초과는 `InputTooLong`으로 기록한다.
* 원문 반박과 전체 단위 복귀는 무효화로 처리한다. 과부하 누락과 구분한다.

IPC 기록 버퍼는 128개다. 스냅샷 수락이 이 버퍼를 지우지 않는다.
앞단은 최근 64개 세그먼트의 상태를 보관한다. retired 세그먼트는 재생하지 않는다.
worker의 이벤트 유실과 이미 덮인 부분 번역은 최신 history만으로 복원할 수 없다.
버퍼 초과 수와 로그 누락을 함께 확인해야 한다.

비교, 모델 설정 실패의 실제 UI 복원, macOS 검증은 후속 범위다.
