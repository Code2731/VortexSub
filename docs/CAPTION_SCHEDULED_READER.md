# 재사용 증거를 소비하는 줄 배정기

2026-10-10. `CaptionScheduledLines`의 계약이다.
[입력 저장소](CAPTION_INPUT_CONTRACT.md)와 [문장 재사용](CAPTION_SENTENCE_REUSE.md)을 사용한다.
실제 `OverlayWindow`의 진단과 MainWindow live 경로에 연결했다. 모의 표시와 기존 회귀는 기존 `CaptionLines` 경로다.

## 수명과 입력

`Begin(context)`으로 세션을 명시한다. `Submit(input, fit)`은 입력을 저장하고 배정을 진행한다.
`Tick(now, fit)`은 같은 단조 시계로 읽기 기한과 대기 입력을 검사한다.
`Invalidate(segment, now)`는 미표시 입력을 취소하고 표시 줄을 기존 기한까지 유지한다.
`withdraw = true`는 해당 표시 줄을 지운다. `Stop`과 세션 변경은 상태를 초기화한다.
새 세션은 `Begin`이 필요하다. 이전 입력으로 자동 재개하지 않는다.
한 UI 스레드에서 사용한다. 오디오 콜백에서 사용하지 않는다.

## 배정 규칙

두 줄의 위치는 고정이다. 열린 줄은 같은 접두어일 때만 이어 쓴다.
아랫줄이 남아 있으면 새 글자를 윗줄에 넣지 않는다.
완료한 입력 뒤에는 빈 아랫줄에 다음 입력을 배정할 수 있다.
최소 읽기 시간은 2.5초다. 아랫줄 만료는 윗줄보다 최소 0.25초 뒤다.
교정은 이전 버전의 관련 줄을 읽은 뒤 배정한다.
새 교정 버전의 윗줄은 같은 버전의 아랫줄 배정을 막지 않는다.

재사용 범위 앞에서 배정 내용을 나눈다. 변경된 문장을 먼저 표시한다.
그 뒤 `Store.Reuse`로 실제 이력을 검증한 문장만 건너뛴다.
재사용 증거가 퇴역하면 남은 내용을 표시하는 경로로 돌아간다.
배정 또는 재사용으로 끝까지 전달해야 완료한다.
재사용은 읽기 줄과 기한을 변경하지 않는다.

폭 측정 결과가 문자소 중간이면 문자소 경계로 보정한다.
글자 추가는 기존 화면 Run을 유지하는 오버레이 렌더 경로를 사용한다.
개행만 추가되면 읽기 기한을 연장하지 않는다. 이 예외로 일반 글자의 보호 시간을 줄이지 못한다.
줄 앞의 공백·CRLF는 빈 읽기 슬롯 없이 소비한다.
분리자 전달은 `Separator = true`, `Slot = -1`로 이력에 기록한다.
분리자는 사라진 번역 본문이나 임의 완료 범위가 아니다.

## 상한과 진단 연결

본문·이력·큐의 기존 저장 상한을 사용한다. 화면 행은 두 개다.
한 Tick은 최대 8단계다. 남은 작업은 다음 Tick에서 계속한다.
재사용 후보는 현재 토큰 하나만 보관한다. 새 토큰이면 다시 비교한다.
시간 상수 조정으로 용량 제약을 없애지 않는다. 과부하는 기존 사유별 카운터로 기록한다.
실제 UI 스레드 시간·메모리와 자연 음성의 대기 효과는 아직 측정하지 않았다.

`OverlayWindow.BeginScheduledReading` 이후에는 진단 입력만 받는다.
같은 창에서 기본 `SetCards`를 섞으면 거부한다.
자동 화면 실행은 Desktop의 `--caption-schedule-report <새 경로>`다.
통합 실행은 저장소 루트의 `& scripts/test-captions.ps1`이다.
후보 PNG·픽셀 보고서는 `candidate-render/`에 저장한다. 모델을 사용하지 않는다.
