같은 알려진 표시 단위에서 target의 앞 문장이 글자까지 동일하면 읽기 보호 후
그 문장은 재사용하고 변경된 문장부터 표시한다. 첫 문장 변경/짧아진 final은 전체

규칙은 재사용 가능한 동일 문장이 없는 경우 적용한다.

## 표시 규칙

사용자가 요청한 **두 줄에 이어 쓰고 읽은 줄부터 제거** 방식을 오버레이에 적용했다.
번역 입력과 화면의 읽기 줄은 별도 상태다. 완성된 번역 문자열을 매번 화면 전체에
대입하지 않고 화면 폭/폰트로 측정한 한 줄 조각을 빈 줄에 배치한다.

* 두 TextBlock은 항상 같은 위치/높이를 유지한다. 빈 줄도 접지 않는다.
  높이는 42 DIP, 본문 line height는 36 DIP로 지정해 이모지 폰트로 높이가 늘지 않게 한다.
  실제 픽셀 크기는 화면 배율에 맞춰 반올림된다.
* 완성된 줄은 **최소 2.5초** 읽는 동안 바꾸지 않는다. 작성 중인 마지막 줄은
  기존 문자를 지우지 않고 뒤에만 붙이며 추가 시 읽기 시간을 연장한다. 두 줄을 같이 채운 경우
  아래 줄의 만료를 0.25초 늦춰 먼저 표시한 줄부터 제거한다. 남은 줄은 옮기지 않는다.
  아랫줄이 남아 있으면 빈 윗줄에 새 내용을 넣지 않는다. 읽기 종료 후 위에서부터
  다시 채워 새 내용이 이전 내용보다 위에 나타나는 순서 역전을 막는다.
  이 보호 때문에 후속 표시가 추가로 대기할 수 있다.
* LF/CRLF/CR은 다음 줄로 넘기는 신호로 소비하며 TextBlock 본문에 넣지 않는다.
  빈 줄은 읽기 슬롯을 차지하지 않는다. 결합 문자/이모지 묶음 경계를 보존한다.
* 같은 번역 단위의 새 결과가 이미 표시한 문자 prefix를 유지하면 추가된 뒤쪽을
  이어 표시한다. 입력 카드에서도 이 추가는 1.25초 전체 교체 제한을 기다리지 않는다.
  prefix가 달라졌으면 임의로 서로 다른 번역을 합치지 않고 현재
  읽기가 끝난 뒤 최신 교정 내용을 새 줄로 표시한다.
  같은 식별자의 입력을 모두 표시한 뒤 끝 마침표 하나만 바뀌면 기존 본문과
  읽기 기한을 유지한다. 숫자·약어·질문·감탄·말줄임표는 이 예외에서 제외한다.
  revision 정보는 갱신한다. 뒤의 글자 변경은 실제 표시한 본문과 다시 비교한다.
  실시간 앱은 새 단위/일반 교정도 즉시 표시기로 넘긴다. 입력 단계의 1.25초
  교체 대기를 중복 적용하지 않으며 마침표 묶기 옵션의 0.75초 기한만 별도로 둔다.
* 서로 다른 번역 단위는 최대 4개·10초 대기한다. 같은 단위의 수정본은 합친다.
  현재 입력을 모두 표시했고 윗줄만 남아 있으면 다음 단위를 빈 아랫줄에 바로 넣는다.
  현재 입력에 미표시 꼬리나 정정이 있으면 먼저 처리한다. 남은 윗줄을 지우거나
  아랫줄로 옮기지 않는다. 두 줄이 차 있거나 아랫줄만 남아 있으면 다음 단위는 기다린다.
  입력은 16,384 UTF-16자로 제한한다. 표시한 줄을 일찍 지우지 않는다.
  상한을 초과하면 미표시 단위 또는 꼬리를 제거하고 사유를 기록한다.
  두 줄이 비었을 때 남은 꼬리가 한 줄에 들어가면 10초가 지났어도 먼저 표시한다.
  다음 단위는 빈 아래 줄에 이어 표시한다. 여러 줄이 남으면 기존 상한을 적용한다.
  [리뷰 개선 계획](REVIEW_IMPROVEMENT_PLAN.md)의 대기 정책을 따른다.
* 원문 prefix 진단은 화면 전체 지우기를 실행하지 않는다. 번역 prefix 수정은
  읽기 후 최신 교정으로 전환하며 그동안 보인 임시 내용이 잠시 남을 수 있다.
  Pause/Stop/통신 오류/세션 변경은 줄을 즉시 지운다.
  일반 입력 카드 만료는 이미 받아 둔 번역의 남은 줄을 버리지 않는다.
  다음 유효 번역이 오면 다른 단위를 대기열에 넣는다. 현재 번역의 미표시 부분을
  먼저 읽는다. 과부하 시 미표시 부분의 기한은 위 대기 정책을 따른다.
  번역 없는 카드/무효화는 이전 입력의 추가 표시를 중지하되 보이는 줄의 읽기는 유지한다.
* 원문 표시는 기본 꺼짐이며 켜면 번역 두 줄 아래에 표시한다.
  상태 접두사와 이전/현재 라벨은 번역 본문에 넣지 않는다.

Unicode 문자 경계로 나누고 가능한 경우 단어 경계를 선택한다. 표시 중 창 폭을
줄여도 이미 읽는 줄을 재분할하지 않으므로 좁아진 폭에서 잘릴 수 있다.
후속 줄부터 새 폭을 적용한다. 표시 줄의 고정은 번역 의미의 확정을 뜻하지 않는다.

## 기록과 확인 범위

timing의 `caption_line_assigned`는 상/하 줄의 실제 TextBlock 대입 시각, 식별자와
UTF-16 글자 수만 기록한다. 자막 문자열은 기록하지 않는다. 기존 `deck_applied`는
줄 표시기에 공급되는 입력 시각이며 이 모드에서 줄 표시 시각과 같지 않다.
기존 요약기의 deck 통계를 실제 줄 표시 지연으로 해석하지 않는다.
2026-10-03 `caption_reading` 진단을 추가했다. `FirstLine`은 논리적 첫 줄 입장이다.
첫 입력부터 입장까지의 `reading_wait_s`를 기록한다. 숨겨진 오버레이의 입장은
표시 대기 통계에서 제외한다. `Dropped`의 사유와 `Invalidated`를 구분한다.
`TailRetained/FitsOneLine`은 시간 상한 뒤 한 줄 꼬리를 보존한 관측이다.
짧은 꼬리 뒤의 다음 단위는 같은 갱신에서 빈 아래 줄에 넣는다.
갱신당 추가 처리는 한 번으로 제한한다. 한 번에 대기열 전체를 비우지 않는다.
`Blocked`는 대기열 첫 단위의 대기 상태가 바뀔 때 기록한다. `Correction`,
`UnitTransition`, `BothLinesProtected`, `LowerLineProtected`, `UpperLineProtected`,
`UnreadTail`을 구분한다. 요약의 `blocked_state_transitions`는 전이 횟수이며
각 상태의 총 대기 시간은 아니다. 과거 로그의 빈 값은 대기가 없었다는 뜻이 아니다.
`BlockEnded.blocked_s`는 종료된 대기 상태 한 구간의 초 단위 기간이다.
요약의 `closed_block_duration_s`는 원인별 구간 통계다. 중지/초기화/로그 종료 시
열린 구간은 포함하지 않는다. 종료 시 오버레이가 보인 구간만 집계한다.
`CorrectionApplied`는 실제 정정 적용과 동일 앞 문장 재사용 글자 수를 기록한다.
`CosmeticRetained/TerminalFullStop`은 끝 마침표 변경만으로 재표시하지 않은 관측이다.
이 값은 의미 오류 판정이 아니다. 표본 상한을 넘으면 `sample_window_warning`이 true다.
`caption_event_buffer`는 worker별 UI 기록 버퍼의 누적 초과 수다.
이 기록은 **자막 지연 기록**을 켰을 때 저장한다. 자막 문자열은 저장하지 않는다.
2026-10-04부터 각 줄에 해당 줄의 식별자를 기록한다. 서로 다른 단위를 두 줄에
표시할 때 윗줄에 최신 단위 식별자를 잘못 붙이지 않는다.

2026-10-02 전체 check, 표시 상태 테스트, 실제 Avalonia 렌더링 fixture와 저장된
픽셀 비교를 실행했다. [명령과 결과](evidence/caption-line-verification-windows-20261002.md).
Windows 합성기의 연속 프레임과 장시간 실제 읽기는 미확인이다. ASR/번역 요청 정책은
기존이며 이 변경으로 전체 원문의 재번역이나 의미 교정이 사라지는 것은 아니다.

## 깜빡임 원인 검토와 수정 (2026-10-02)

사용자 로그 `caption-timing-20261002-223320-20946a66604440479adfeb4d9a6f70bd.jsonl`의
줄 대입 110건 중 지우기 49건, source guard 진단 19건을 확인했다.
지우기 31건은 진단과 0.15초 이내였다. 이는 메타데이터 상관이며 실제 프레임 검증은 아니다.
코드에서는 진단 이벤트가 전체 줄 Clear를 호출했고, 번역 없는 준비 상태도 Clear했다.
두 경로를 제거했다. 기존 줄의 수명과 새 글자의 도착을 분리해야 한다.

표시 연산은 다음처럼 구분한다.

| 입력/상태 | 표시 연산 |
| --- | --- |
| 표시한 prefix를 보존한 추가 번역 | 작성 중인 줄에 glyph Run 추가; 넘치는 suffix는 빈 줄에 배치 |
| 이미 읽는 prefix의 수정 | 최신 교정 하나를 보류; 읽기 후 교정 |
| 번역 없는 카드 | 새 줄 생성 중지; 보이는 줄 유지 |
| 일반 입력 카드 만료 | 받아 둔 최신 번역의 남은 부분 읽기 계속 |
| 읽기 시간 만료 | 해당 줄만 만료; 다른 줄 위치 유지 |
| 세션/epoch 변경, 중지/오류 | 전체 Clear |

원문 표시가 꺼져 있으면 숨겨진 원문 Text를 매번 대입하지 않는다.
스크롤 초기화도 입력 가설이 아닌 실제 표시 단위 변경에 연결했다.
실제 렌더링 확인 중 마지막 줄이 한 글자에서 멈추는 문제를 발견해 suffix append를 수정했다.
완성된 줄은 고정하고 열린 줄은 기존 Run을 제거하지 않고 추가한다. 상태/렌더링 검사와
전체 check가 통과했다. 교정/새 epoch 스냅샷은 UI 배치 완료 후 저장하고 픽셀도 비교했다.
GPU/합성기의 redraw 원인은 확인하지 않았으며 모든 깜빡임 해결을 주장하지 않는다.

후속 연속 갱신 fixture에서는 각 글자 추가 단계와 긴 문장의 줄 전환을 저장했다.
줄바꿈으로 인한 높이 증가, 이모지 폰트의 높이 증가, 새 윗줄/이전 아랫줄의 순서 역전을
수정했다. [연속 갱신·긴 문장 검증](evidence/caption-line-stream-windows-20261002.md).

2026-10-03 입력 카드와 줄 표시기를 함께 연결해, 입력 수명이 끝나면서 긴 번역의
뒷부분이 누락되는 문제를 수정했다. 부분 번역의 단순 추가에는 입력 단계의 전체
교체 대기를 제거했다. [연결 검증과 범위](evidence/caption-pipeline-windows-20261003.md).
