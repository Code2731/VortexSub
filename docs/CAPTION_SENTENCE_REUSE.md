# 자막 문장 비교와 재사용 증거

2026-10-10. `CaptionSentenceReuse`와 `CaptionScheduleStore.Reuse`의 계약이다.
[입력 계약](CAPTION_INPUT_CONTRACT.md)의 후속 구현이다. 현재 제품 표시기에는 연결하지 않았다.
후속으로 [후보 줄 배정기](CAPTION_SCHEDULED_READER.md)와 오버레이 진단에 연결했다. 기본 live/mock은 기존 표시기를 사용한다.

## 비교 범위

같은 단위의 이전 표시 이력과 최신 번역을 비교한다.
이전 버전은 최신 번역과 다른 revision/request 중 가장 최근 버전이다.
최신 번역의 교정 앞문장을 배정한 뒤에도 이전 버전을 비교 기준으로 유지한다.
표시 이력은 시작 0부터 연속해야 한다. 이력이 잘렸거나 중복되면 증거를 만들지 않는다.
원문 범위와 기준 revision이 같아야 한다. 다른 발화·부분 단위의 이력을 합치지 않는다.
범위 미상·겹침·원문 수정에는 전체 교정 후보를 유지한다.

문장 끝은 마침표·물음표·느낌표·CJK 문장 부호·개행으로 나눈다.
닫는 따옴표와 뒤 공백은 해당 조각에 포함한다. 열린 마지막 조각은 재사용하지 않는다.
소수점과 지정한 약어는 문장 끝으로 나누지 않는다. 문자소 중간을 자르지 않는다.
이 규칙은 완전한 다국어 문장 분석기가 아니다. 보수적으로 재사용을 포기할 수 있다.

## 재사용 조건

문자열은 ordinal로 정확히 비교한다. 숫자·부정 표현·띄어쓰기의 의미 동등성을 추측하지 않는다.
닫힌 문장 조각의 LCS를 계산한다. 같은 문장은 이전과 같은 문장 순번이어야 한다.
문장 수 감소·문장 이동·중간 삽입·중복 문장이 있으면 재사용 증거를 만들지 않는다.
순서 변경 거부에만 앞뒤 공백을 제거해 비교한다. 공백 제거로 재사용을 허용하지 않는다.
문장 내부 변경은 해당 문장을 다시 표시해야 한다. 모든 의미적 삭제를 판별한다는 뜻은 아니다.

입력·기준 본문은 각각 최대 16,384 UTF-16 단위다. 조각은 각각 최대 64개다.
LCS 행렬의 내부 셀은 최대 4,096개다. 경계 행/열을 포함한 배열은 최대 65×65다.
후보 객체는 호출자가 보관한다. 저장소는 후보 본문이나 행렬을 보관하지 않는다.
모델 호출·의미 추론·오디오 처리는 하지 않는다. UI 스레드의 실제 비용은 아직 측정하지 않았다.

## 증거 소비

`Analyze(snapshot)`은 사유와 `CaptionReuseProof`를 반환한다.
증거에는 현재 토큰·원문과 표시 이력의 해시·재사용 범위가 들어 있다.
범위 목록은 읽기 전용이다. 호출자가 만든 임의 범위를 완료 근거로 사용하지 않는다.
`Reuse(proof, start, end)`는 현재 토큰과 최신 표시 이력을 다시 비교한다.
현재 진행 위치에서 시작하는 증명된 범위 하나만 소비한다.
교정 앞문장을 건너뛰거나 같은 범위를 두 번 소비하지 못한다.
교체·세션 변경·이력 퇴역으로 증거가 달라지면 거부한다.

재사용은 화면 줄과 읽기 기한을 바꾸지 않는다.
새 버전의 전달 이력은 `Reused = true`, `Slot = -1`로 기록한다. 실제 줄 배정과 구분한다.
이 이력도 기존 문자·조각 상한에 포함한다. 다음 번역은 이 전달 이력을 다시 검증할 수 있다.
저장 예약 실패는 진행 위치를 유지한다. 이력이 잘리면 추가 재사용을 중단한다.
`Complete`는 실제 배정 또는 검증된 재사용으로 끝까지 전달했을 때만 성공한다.
이미 동일한 전체 본문을 표시한 입력은 기존 진행 위치를 사용한다. 중복 재사용은 거부한다.

## 원문 교정의 앞문장 증거 (2026-10-10)

`AnalyzeLeadingPrefix`는 동일 원문 LCS와 별도 증거 종류다.
같은 단위의 현재·이전 원문 범위가 모두 시작 0이어야 한다. 원문 범위를 추측하지 않는다.
실제 전달 이력이 시작 0부터 연속이어야 한다. 모든 조각의 이전 원문 범위가 같아야 한다.
이력이 불완전하거나 원문 범위가 미상이면 전체 교정을 유지한다.
문장 수 감소·열린 앞문장·변경된 앞문장은 재사용하지 않는다.
닫힌 문장이 처음부터 ordinal로 정확히 같을 때 연속 앞부분 하나만 재사용한다.
다른 위치의 같은 문장이나 다른 부분 단위의 이력은 이 증거로 재사용하지 않는다.
변경된 뒤 문장은 실제 배정해야 한다. 의미 동등성이나 원문 문장 대응을 증명하지 않는다.
입력·조각·저장 상한과 토큰·해시 재검증은 기존 계약을 따른다.
앞문장 증거는 화면 줄과 읽기 기한을 바꾸지 않는다.
기존 16개 golden 전체와 후보·기록 어댑터 저장 화면이 통과했다.
