작성일: 2026-10-02. 대상: 개인 개발·비상업적 평가용 Windows / RTX 3080 10 GB.

## 1. 목표와 현재 기준선

목표는 한국어 의미 오류를 줄이고, 음성에서 읽을 수 있는 자막까지의 지연과
불필요한 수정을 줄이는 것이다. 품질·속도·읽기 안정성을 별도로 판정한다.

* 기본 대조군: Qwen3-4B-Instruct-2507 Q4_K_M + 기존 llama.cpp.
* ASR 대조군: 기존 Whisper CUDA 빠른 모드. 비교 중 ASR/패딩/문맥/표시 설정을
  동시에 바꾸지 않는다. 실험 옵션은 실행별로 명시한다.
* 정상 세션의 처리 중앙값: ASR 0.1083초, 번역 HTTP 0.1733초.
  음성 시작→첫 요청의 대기와 물리적 화면 출력까지를 포함한 값은 아니다.
* 원문 LocalAgreement, 조건/부정 꼬리 보류, 두 카드 읽기 보호는 이미 있다.
  `translation_prefix`는 원문 guard이며 확정된 한국어 prefix가 아니다.
* Qwen 1.7B/TranslateGemma 비교와 Laya 오류 검출은 이미 진행했다.
  새 근거 없이 같은 비교를 반복하거나 Laya를 자막 차단기로 연결하지 않는다.

## 3. 실행 순서

| 단계 | 산출물 | 다음 단계 조건 |
|---|---|---|
| P0. 비교 기반 | 누락 구간 계측, 공통 평가 자료, 입력 계약 기록 | 요청·시간 정의와 대조군이 재현 가능 |
| P1. 모델 비교 | Qwen / EXAONE / Hy-MT2의 언어별 품질·처리시간표 | 채택 가능 후보 또는 명시적인 유지 결정 |
| P2. 번역 수정 정책 | target draft/수정 범위 진단과 선택형 정책 | 의미 반전·읽기 손상 없이 개선 확인 |
| P3. 앱 연결 | 채택 모델/정책 선택, 적용 상태와 복귀 경로 | 실제 파일→앱 표시와 개인 사용 확인 |
| P4. QE 진단 | MetricX 한국어 판별 자료와 연결/보류 결정 | 판별력·추가 비용이 확인될 때만 후속 연결 |

최초 순서는 P0부터였으며 현재는 P1/P3의 실제 입력 검증을 진행 중이다.
P1은 P0의 입력/평가 자료를 필요로 하지만
모든 라이브 계측이 끝날 때까지 미루지 않는다. P2의 진단은 기존 Qwen으로도
가능하며, 최종 채택 판정은 P1의 선택 구성으로 다시 확인한다.

## 5. P1 — EXAONE·Hy-MT2 비교

### 후보와 실행 계약

| 모델 | 역할 | 입력과 범위 |
|---|---|---|
| Qwen3 4B Q4_K_M | 현재 대조군 | 현 기본 요청. IsolatedContext는 별도 비교축 |
| EXAONE 3.5 2.4B Q4_K_M | 사용자 제안 한국어 후보 | 공식 system/template/EOS, repetition penalty 1.0. 영어 우선, 일본어는 탐색 결과로 구분 |
| Hy-MT2 1.8B Q4_K_M | 번역 특화 후보 | 공식 user 번역 지시와 배경 문맥. 영어/일본어 각각 판정 |

EXAONE은 개인 개발·연구 평가용 비교군으로 동등하게 평가한다. 라이선스 때문에
비교 순위를 낮추지 않는다. 배포/다른 목적의 허용 여부는 이 실험의 성능 판정과 별개다.
Hy-MT2의 1.25-bit/STQ는 첫 비교에서 제외한다. 실제 다운로드는 공식 배포 revision·
크기·SHA-256·런타임 변경 필요를 확정하고 AGENTS.md의 동의를 받은 뒤 수행한다.
현재 EXAONE Q4_K_M은 약 1.64 GB, Hy-MT2는 약 1.13 GB다. Hy-MT2는 dense
지원이 있는 별도 llama.cpp b11146/CUDA 12.4 ZIP 약 645.31 MB를 승인 후 설치했다.

- [ ] P1.1 모델별 catalog와 입력 profile을 추가한다.
  - EXAONE 설치·6047 template/EOS·CUDA, 로컬/서버 렌더링 토큰열과 chat 입력 개수·공통 greedy 확인 완료. 내부 chat 토큰열 직접 노출은 없으며 권장 sampling과 Hy-MT2는 남아 있다.
  - 현 llama.cpp build 6047의 architecture/template/EOS를 확인한다.

    공식 template를 못 쓴 결과는 품질 비교에서 제외한다.

    seed가 지원되지 않거나 실행이 결정론적이지 않으면 그 한계도 기록한다.

* 모든 후보를 순서대로 자동 설치하지 않는다. 해당 조건이 충족된 후보만 준비한다.

검증 명령은 기존 `scripts/check.ps1`, 모델별 probe, paced replay와 caption timing
요약을 사용하고 새 명령은 구현한 뒤 실행법을 문서화한다. 테스트/실제 비교는
후속 구현·검증 요청 범위에서 실행한다. 이번 계획 작성 중 테스트는 실행하지 않았다.
원문/번역·오디오·full 결과는 Git 제외 경로에 두고 기본 timing에는 텍스트를 넣지 않는다.
증거 요약만 `docs/evidence/`에 기록한다. 관련 OS/하드웨어와 미실행 범위를 남긴다.

## 10. 다음 라운드

2026-10-03 종합 리뷰 후속은 [리뷰 개선 계획](REVIEW_IMPROVEMENT_PLAN.md)에 연결했다.
설정 커밋 실패 복구, 정정 길이 경계, VAD 처리 시작/완료 분리와 제한된 자막
대기 정책을 구현한다. 해당 구현·검증은 전체 P3.2 또는 v1.0 완료와 구분한다.

EXAONE은 문맥 구분/제거 비교까지 수행했고 새 오류로 채택을 보류했다.
Hy-MT2는 고정 asset/입력 계약과 greedy/공식 권장 sampling 비교를 완료했다.
P1.3 고정 partial trace 입력/재생과 반복 비교, P2.1 변경 진단 구현을 완료했다.
P2.2 제한 후보와 P2.3 paired 경로를 구현했으나 같은 입력 20회에서 효과가 없어
기본 채택과 넓은 본문 동결은 보류한다. P3.1의 명시적인 실험 모델/profile
선택 경로와 줄 표시 회귀를 확인했다. paced PCM 비교에서 조건문 대기는 번역 엔진보다
부분 전사의 변동/안정 구간 보류가 큰 사례를 확인했다. ASR 변경 원인을 분류했고
Whisper small의 빠른 안정화와 조건 누락 경로를 확인·보완했다. 다른 합성 6문장
72회 비교에서는 기본 ASR 변경 근거가 부족했고 정정 단위 문제가 드러났다.
관측된 정정 표지와 다음 절의 묶기/보류를 구현했고 직전 원문을 포함한 재번역으로
12회 실제 재생을 확인했다. 이 기록의 원문/번역 갱신을 앱 두 줄 표시/읽기 보호에
재생해 상태와 픽셀 회귀를 확인했다. 실제 시간 MainWindow/IPC 세션 재시작과
Worker 끊김·재연결은 모의 입력으로 확인했다. 다음은 모델 설정 실패 복원과 실제
음성 부하 확인이다. 모의 모델/캡처 준비 및 저장 렌더를 native 부하 또는
물리 연속 화면 검증으로 간주하지 않는다.
관리되는 자연 음성 자료는 아직 없어 별도 확보가 필요하다. 조건 보호는 유지한다.
이후 실제 파일→앱 표시와 P3.2의 세션/장시간 확인을 진행한다.
언어별 독립 품질 판정과
새 paced PCM→ASR→번역 비교는 별도로 남겨 둔다.
전체 독립 품질 검토는 남겨 두되
EXAONE의 반복 prompt 튜닝으로 후보 비교를 지연시키지 않는다.
실제 라이브 timing 수집은 모델 비교와 별도로 진행하며 모든 계측 완료를 기다리지 않는다.
Hy-MT2 모델과 별도 b11146 runtime은 승인 후 설치·비교를 완료했다.
앱의 새 추론 경로는 선택형 실험으로 연결했으며 기본 전환은 하지 않았다.
