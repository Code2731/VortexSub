# 실제 번역 세션 확인 — P3.2

## 기록하며 실행

빌드된 앱은 기존 배치파일로 실행한다. 상태 기록을 함께 남기려면:

```powershell
./run-live-hymt2.bat -NoBuild -CaptionTiming
```

앱에서 서버 연결 후 **Hy-MT2 전용 입력 / Ready**를 확인하고
**안정된 부분 먼저 번역 · 임시 결과**를 켠다. 원문 오버레이는 기본 꺼짐이다.
기록 옵션은 앱 설정에서도 켜고 끌 수 있다. 파일 경로는 설정 화면에 표시한다.

## 확인 순서

1. 알고 있는 영상/음성으로 부정, 조건, 수량, 행동 주체가 보존되는지 확인한다.
   예: “도착하기 전까지 떠나지 마라”가 “도착하면 떠나라”로 바뀌는지 구분한다.
2. 읽기 전에 자막이 바뀌거나 사라지는 사례가 있으면 영상 시각과 현상을 적는다.
   의미 교정에 필요한 변경과 같은 뜻의 반복 변경을 구분한다.
3. 최소 30분 사용 중 일시정지→재개를 수행한다. 잠깐 정리 후 다시 시작되는지,
   이전 자막이 나타나지 않는지 확인한다.
4. 세션 종료→새 세션 시작을 같은 앱에서 수행한다. 모델과 입력 설정이 유지되고
   새로운 자막만 나타나는지 확인한다. 기록 옵션을 유지해 전후를 함께 남긴다.
5. 설정 실패 복원을 확인하려면 Idle에서 Hy-MT2 모델을 둔 채 **Qwen 고정 생성 설정**을
   선택하고 적용한다. 이 모델/profile 조합은 거절되어야 한다.
   오류 후 기존 적용 모델/입력과 Ready가 유지되는지 확인하고 원래 선택으로 돌아간다.
   실제 가중치 변경은 앱 종료 후 해당 런처를 다시 실행한다.

게임 동시 실행 여부와 source 언어를 함께 적는다. 품질 문제는 원문/번역과 시각을
별도 개인 메모에 남긴다. timing 로그에는 자막 문자열과 endpoint/token을 넣지 않는다.

## 요약

```powershell
./models/tabby/venv/Scripts/python.exe -X utf8 ./scripts/summarize-caption-timing.py ./logs/caption-timing-파일명.jsonl
```

`session_epochs.observations`는 worker/session/epoch별 적용 모델/profile 관측,
번역 완료·오류·취소, 자막 변경 종류, UI 문맥 일치 여부를 나눈다.
상태 변화는 즉시 기록하고 변하지 않는 상태는 약 5초마다 기록한다.
`deck_clear_requests`는 시작/일시정지/종료 버튼에서 자막을 비운 요청 횟수다.

`context_mismatches`는 카드 적용 당시 마지막으로 UI에 적용한 상태와 식별자가
달랐다는 관측이다. 실제 픽셀 혼입을 입증하는 값은 아니다.
`context_unreported_applications`나 drop/eviction이 있으면 전체 확인으로 해석하지 않는다.
기존 로그의 모델/profile/오류 필드 부재도 정상이나 오류 0으로 해석하지 않는다.
취소되거나 적용되지 않은 완료는 정상적인 세션 전환에서 발생할 수 있다.

기간과 p95는 초이며 기록 범위·관측 수를 함께 읽는다. span은 지속 Running 시간이
아니고, pending 입력은 표본값이며 전체 큐/메모리나 GPU 경쟁을 측정하지 않는다.
번역 품질, 물리적 화면 지연, 30분 안정성은 이 요약만으로 자동 통과하지 않는다.

## 현재 확인 범위

2026-10-02 사용자는 Hy-MT2 실행 후 체감 속도 개선을 보고했다. 수치나 품질/장시간
안정성을 확인한 보고는 아니다. 새 기록 경로는 C# 빌드까지 완료했고 기존 약
504.364초 로그는 요약 오류 0으로 처리했다. 이전 로그에는 새 문맥 필드가 없어
338건 카드 적용의 세션 일치를 판정할 수 없다. 새 앱 실행과 실패 복원 분기,
30분 세션·게임 경쟁·macOS, 자동 회귀 테스트는 아직 실행하지 않았다.
