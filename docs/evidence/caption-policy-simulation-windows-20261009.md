# 자막 표시 정책 시뮬레이션

2026-10-09, Windows x64. 제품 표시기를 바꾸기 전에 후보를 비교했다.
[조사](caption-algorithm-research-20261009.md)와 [계획](../CAPTION_SCHEDULING_PLAN.md)을 따른다.

## 결론

S1의 제한된 문장 재사용을 제품 입력 계약 구현의 다음 후보로 선정했다.
고정 입력에서 같은 뒷문장의 재배정을 없앴다. 다음 발화의 대기도 줄었다.
꼬리 합의 S2와 끝부분 보류 S3는 지연 증가 사례가 있어 기본 정책으로 선정하지 않았다.
실제 음성 개선이나 제품 적용 완료를 뜻하지 않는다.

## 구현과 비교 조건

검사 전용 `tests/EchoSub.ProtocolSmoke/CaptionPolicySimulation.cs`를 추가했다.
`scripts/simulate-caption-policies.ps1`로 실행한다. 제품 코드와 개인 설정은 변경하지 않았다.

| 정책 | 동작 |
| --- | --- |
| S0 | 현재 `CaptionLines`를 직접 호출한다. |
| S1 | 표시 이력·미표시 작업을 분리한다. 같은 문장을 제한된 LCS로 재사용한다. 빈 줄에 작업을 배정한다. |
| S2 | S1에 연속 번역의 문장 prefix 합의를 적용한다. 첫 조각은 바로 허용한다. final은 합의를 기다리지 않는다. |
| S3 | S1에서 미완성 꼬리의 마지막 6개 문자소를 보류한다. 모델 토큰 mask-k의 재현은 아니다. |

입력은 `CaptionDeck` 뒤의 번역 전달 경계다. 음성 입력부터의 재생은 아니다.
모든 정책에 같은 본문·시각·revision·segment·unit·epoch를 넣었다.
줄 폭은 32개 문자소다. 가상 시계 간격은 0.1초다. 글꼴의 실제 폭을 재현하지 않는다.
두 줄 위치, 2.5초 보호와 0.25초 만료 간격을 유지했다.
빈 아랫줄 사용과 열린 줄 덧붙이기는 현재 제품에도 있다. 새 기능으로 집계하지 않는다.

대기 작업은 현재 작업 외 4개, 입력은 16,384 UTF-16 단위, 비교 조각은 64개로 제한했다.
이력은 식별자 64개까지 유지한다. 퇴역한 구간의 늦은 입력을 거부한다.
반복 문장, 짧아진 final과 불명확한 원문 단위 겹침에는 전체 교정을 사용한다.
상태의 문자열 동일성은 의미 정확성의 판정이 아니다.

## 실행 결과

22개 고정 입력 × 4개 정책 = 88개 비교가 상태 판정을 통과했다.
원문 수정, 숫자·부정 교정, 미표시 꼬리 철회, 반복 문장, 오래된 revision/segment,
원문 단위 겹침, Unicode, 중지·epoch, 긴 줄과 과부하를 포함했다.
가상 30분에는 600개 문장을 넣었다. 후보 이력은 64개를 넘지 않았다.
정상 비교에서 조기 삭제와 보호 중 줄 이동은 0건이었다.
과부하 외 요구 출력 누락은 없었다.

| 고정 사례 | S0 | S1 | S2 | S3 |
| --- | ---: | ---: | ---: | ---: |
| 앞 문장 교정 뒤 다음 발화 대기 | 4.9초 | 2.1초 | 4.6초 | 2.1초 |
| 같은 뒷문장 반복 배정 글자 | 10 | 0 | 0 | 0 |
| 추가 뒷문장 대기 | 0초 | 0초 | 0.4초 | 0초 |
| 짧은 미완성 첫 자막 대기 | 0초 | 0초 | 0초 | 1초 |

첫 사례의 **교정 자체 대기**는 S0/S1 모두 2.3초였다.
이 개선은 동일한 뒷문장이 슬롯을 다시 차지하지 않아 다음 발화가 일찍 들어간 결과다.
S1에서 문장 재사용만 제거하면 다음 발화 대기는 다시 4.9초다.
S1에서 빈 아랫줄 배정만 제거하면 4.6초다. 두 기여를 별도 대조군으로 확인했다.

12개 빠른 발화의 용량 과부하에는 모든 정책에서 `QueueCapacity` 폐기 6개가 있었다.
긴 꼬리 과부하에는 `UnreadTailAge` 폐기 1개가 있었다.
이 내용은 `missing`과 `accounted_unshown`에 남겼다. 무누락 통과로 해석하지 않는다.
일반 상태 판정 통과와 지연 채택 판정은 별개다. S2/S3는 지연 채택 판정을 통과하지 못했다.

## 판정 도구 확인

보호 중 교정을 덮어쓰는 고장 대조군에서 `reading_deadline` 실패를 검출했다.
최종 숫자·부정 교정을 버리는 고장 대조군에서 `required_output_missing` 실패를 검출했다.
검사 수정 중에는 동일 문장이 두 슬롯에 있을 때의 거짓 줄 이동 판정을 제거했다.
표시되지 않은 주장을 삭제한 final에는 불필요한 재표시를 요구하지 않도록 했다.
읽기 기한과 원문 수정이 겹칠 때는 수정 적용 전에 오래된 꼬리를 내보내지 않도록 후보를 보강했다.

S0의 읽기 기한은 검사에서 private `expires`를 읽기 전용으로 관측한다.
한 Tick 안에서 같은 글자가 만료 후 재배정되면 본문 비교만으로 그 배정을 알 수 없기 때문이다.
필드가 없으면 실행이 실패한다. 생산 코드의 해시를 보고서에 기록했다.
반복 글자 수는 논리 배정 수다. 물리 화면의 깜빡임 수가 아니다.
의도적인 반복 문장도 반복 글자로 집계할 수 있다.
입력 erasure는 UTF-16 단위의 원문 trace 지표다. 화면 삭제나 의미 오류의 지표가 아니다.
