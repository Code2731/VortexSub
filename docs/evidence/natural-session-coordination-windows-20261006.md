# 준비 세션과 재생 기록 분리

2026-10-06. Windows x64. 로드맵 1단계의 후속 구현이다.

## 변경

- 실제 관찰을 준비 세션 30초와 새 본 측정 세션으로 나눴다.
- 각 세션의 캡처 Running 이후에 별도 재생 기록을 기다린다.
- 실행 ID·단계·자료 URL·확인 시각·본 측정 시작 위치를 검사한다.
- 실행/캡처 준비/재생 확인/본 측정 시작 시각을 구분한다.
- 준비/본 측정 세션 ID가 같으면 실패로 기록한다.
- 기록 개수는 현재 product session ID로 제한한다. 준비 기록은 본 측정에 섞이지 않는다.
- 음성 수신 또는 현재 세션 번역이 없으면 관찰 완료로 처리하지 않는다.
- 보고서 쓰기는 임시 파일을 교체한다. 기존 보고서 경로는 거부한다.
- `scripts/mark-natural-playback.ps1`은 별도 기록을 저장한다. 기존 기록을 덮어쓰지 않는다.

재생 기록은 관찰자의 선언이다. 이 스크립트는 재생/탐색을 수행하지 않는다.
전체 연속 재생, 광고, 언어, 발화량과 물리 화면은 별도 확인해야 한다.
기본 자료는 사용자 지정 영상이고 본 측정 시작은 600초다. 허용 위치 오차는 ±5초다.
재생 선언은 캡처 준비 이후의 최근 10초 확인값이어야 한다. 대기는 120초로 제한한다.
30초 준비가 끝난 뒤 재생 정지와 600초 재탐색은 관찰자가 수행해야 한다.

## 확인 범위

```powershell
$env:AVALONIA_TELEMETRY_OPTOUT='1'
$env:NUGET_PACKAGES=Join-Path $PWD '.nuget/packages'
dotnet build apps/EchoSub.Desktop/EchoSub.Desktop.csproj --no-restore
```

앱 빌드 종료 코드 0. 경고 0 / 오류 0.
PowerShell Parser로 새 재생 기록 스크립트의 구문 오류 0개를 확인했다.
이번 라운드는 테스트를 추가하거나 실행하지 않았다. 앱·서버·실제 캡처도 실행하지 않았다.
준비 세션 전환, 잘못된 기록 거부, 브라우저 협조 실행과 30분 실행은 미검증이다.
캡처 원인 조사는 계속 보류한다. 이전 실패를 이번 실행 결과로 사용하지 않는다.
관련 실행 명령은 [자연 음성 검증](../NATURAL_SESSION_VALIDATION.md)을 따른다.

## 재개

캡처 성공이 확인된 환경에서 새 결과 경로로 실행한다.
브라우저 재생과 관찰 단계 전환을 함께 확인한다. 실제 입력·출력·자원 추이를 기록한다.
보고서·재생 기록·전체 timing 로그는 Git 제외다. 설치 모델과 런타임도 별도 준비한다.
브랜치 master, 기준 HEAD `15f1db0`. 이번 구현과 문서는 미커밋이며 다른 PC에 전달되지 않았다.
