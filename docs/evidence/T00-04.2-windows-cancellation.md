# T00-04.2 Windows 실제 추론 취소·재시작

2026-09-30. 요구 NF-003/004, OPS-001 / `P0-CANCEL`.
범위: Whisper base/small, Windows CPU/CUDA의 독립 probe.
macOS Metal은 실기기 부재로 BLOCKED다. 제품 worker·캡처·UI 통합과
epoch 결과 폐기는 이 실행의 수용 범위가 아니다.

## 구현과 소유권

`AsrEngine::transcribe_cancellable`은 작업마다 새 `Cancellation`을 받으며
완료/취소를 구분한다. `Cancelled` 결과에는 segment를 반환하지 않는다. 이미
사용한 token은 거부하고, 미리 취소한 token은 native 호출을 시작하지 않는다.
취소 요청과 우연히 겹친 일반 native 오류를 취소 성공으로 숨기지 않는다.
완료와 경합한 늦은 요청을 native abort 성공으로 간주하지 않으며, 제품 통합의
늦은 결과 폐기는 별도의 epoch 계약으로 처리한다.

context/state는 한 소유 스레드에서 생성·추론·해제한다. `&mut` 호출과
작업/결과 각 1개 슬롯으로 decode를 직렬화한다. PCM은 immutable `Arc`
작업이 보유한다. 제어 스레드는 원자적 신호만 공유하며, 실행 중 context나
PCM을 해제하지 않는다. 정상 종료는 native 반환→context/state 해제→join
순서다. 다음 작업을 즉시 큐에 넣고 실제 반환/다음 시작/큐 입력 시각을 기록한다.

고정 binding 0.14.4의 `set_abort_callback_safe`는 boxed trait object 주소를
다른 closure 타입으로 해석하고 raw box의 소유권을 보존하지 않는 구현이다.
이 helper를 사용하지 않고 수명이 full 호출까지 유지되는 Arc 주소를 C callback에
빌려준다. callback은 원자적 읽기/쓰기만 하며 context·PCM 접근, 할당, lock,
로그, panic을 하지 않는다. 이 소스 관찰은 다른 binding 버전에 일반화하지 않는다.

## 측정 방법

검증된 `en-01` PCM을 반복/잘라 120초 스트레스 입력으로 만들었다. 품질
시험용 자연 음성이 아니다. 짧은 원본으로 warm-up하고 아래를 모델/경로마다
수행했다. 모든 새 시간 필드와 표시 단위는 **초**다.

1. native encoder-begin callback 관측 후 0.002초 대기→취소→같은 context
   전사 재시작 10회. callback 관측은 encoder 진입 경계이며 실제 기계 명령
   단위의 위치를 보증하지 않는다.
2. native abort check 관측 후 0.002초 대기→취소→같은 context 재시작 10회.
   늦은 취소가 전체 취소 지연의 상한인 것처럼 해석하지 않는다.
3. warm-up한 새 context에서 encoder 진입을 관측한 뒤 정상 종료 10회.
4. probe가 생성한 busy 자식에서 native abort check를 관측한 뒤 그 자식의
   handle만 강제 종료하고, 새 자식의 원본 전사·정상 종료 확인 10회.

모든 취소에는 callback acknowledgement와 native 반환을 요구한다. 복구
전사는 warm-up 문자열과 같아야 하며 다음 decode 시작은 이전 반환 이후여야
한다. 사용 token 거부, pre-cancel의 native check 0, 그 이후 복구도 확인한다.
강제 종료는 active snapshot, 프로세스 생존, full-return marker 부재와 종료
status를 기록한다. marker 부재만으로 종료 순간의 정확한 native 명령을 증명할
수는 없다. timeout/error 때는 이 probe의 자식 handle을 정리한다.
이후 보강한 runner는 고유 실행 디렉터리를 만들며, native harness는 이전
자식 증거 경로를 재사용하지 않고 readiness의 PID·running·native check를
검사한다. 별도 실패 경로 실행에서 오래된 readiness 파일을 새 추론으로
오인하지 않고 자식 생성 전에 거부함을 확인했다. 기존 측정 파일과 hash는
보존하고 해당 보강 binary hash를 summary에 별도로 기록했다.

## 정책과 한계

기본 정책은 **협력 취소 요청 + 소유 스레드에서 native 반환 대기**다.
호출 중 state/context를 파괴하거나 스레드를 강제로 중단하지 않는다. 취소 요청이
즉시 GPU kernel이나 encoder를 중단한다는 보장은 없다. 특히 CPU small의
encoder 시점 취소는 최종 반복 중 약 2.2초 대기가 관찰됐다.

통합 시 캡처/UI 제어는 이 대기를 동기적으로 기다리지 않는다. M1/M2에서
세션/epoch를 무효화하고 큐를 정리하되 PCM은 실행 중 작업이 반환할 때까지
보유한다. 비정상 무응답의 복구 후보로 worker 프로세스 재시작을 유지하며
deadline은 동시 부하와 실제 worker 통합 결과로 정한다. 이 probe로 캡처 Stop
0.5초 목표, UI stale-result 폐기, 모든 시점의 취소 상한을 통과했다고 하지 않는다.
encoder 이전 spectrogram 처리는 별도로 계측하지 않았고 게임 부하·Mac·장시간
메모리 검사는 미실행이다.

재현: `scripts/probe-cancellation.ps1 -Backend cpu|cuda -Offline`.
최종 binary/report/fixture/model hash와 CPU/CUDA 집계는
`T00-04.2-windows-summary.json`, 원본 로그는 `benchmarks/results/`에 보관한다.

`scripts/check.ps1`은 Rust fmt·기존 시험 9개·기본 workspace 빌드,
UI/번역 빌드와 C#↔Rust smoke(Unicode·64요청·종료·worker 죽음)를 통과했다.
native feature는 별도 CPU/CUDA 빌드와 실제 실행으로 확인했다.
일반 ASR 경로도 CPU/GPU 각각 두 모델에 원본 en/ko·무음 소표본을 실행해
정상 전사와 `load_s`/`warm_up_s`/`decode_s`/`audio_s`, segment 좌표의 초
단위 출력을 확인했다. 이는 취소 phase 측정과 별도 실행이다.
