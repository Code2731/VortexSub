# 교정·철회·세션 전환의 장시간 자동 검증 — Windows (2026-10-12)

## 변경과 입력

직접 배정기와 history→Deck→전달 어댑터에 장시간 상태 검사를 추가했다.
각 경로는 6초 간격의 300개 발화를 처리한다. 시계는 가상 1,800초다.
본문과 사건은 고정 합성 입력이다. 새 음원·모델·추론은 사용하지 않았다.
제품의 배정 정책과 읽기 시간은 이번에 변경하지 않았다.

직접 배정기는 다음 6개 흐름을 각 50회 반복한다.

- 반복 교정과 오래된 번역 request의 재도착.
- 원문 revision 변경과 전체 교정 전달.
- 교정 대기 중 명시적 철회.
- 교정이 보인 뒤 명시적 철회.
- 중지 후 같은 context 재개와 이전 토큰·증거 재사용 거부.
- epoch·내부 세션·제품 세션 전환과 이전 context 입력 거부.

기록 전달 경로도 6개 흐름을 각 50회 반복한다.
정상 교정·반복 교정·Failed/Discarded/Skipped·중지 후 재개·context 전환·원문 변경을 사용한다.
이전 기록은 현재 context와 함께 Deck에 전달한다. 실제 기록 필터를 우회하지 않는다.
각 반복에서 배출·대기 큐·단위·조각·문자 예산을 확인한다.
중지 후 상태 정리와 직접 배정기의 Blocked/BlockEnded 수 일치도 확인한다.

## 실패 조사

첫 계약 실행은 기록 전달 경로에서 실패했다.
검증 입력이 `TranslationIsPreview=false`인데 `SourceState=Partial`을 유지했다.
이 조합은 표시 계약에 맞지 않는다. 검증 입력을 `SourceState=Final`로 수정했다.
수정 후 직접 계약 검사와 전체 자막 검사가 통과했다. 이 실패를 제품 결함 수정으로 표시하지 않는다.
초기 결과와 수정 결과는 각각 `benchmarks/results/caption-mixed-contract-20261012.json`,
`caption-mixed-contract-fixed-20261012.json`이다. 기존 결과는 덮어쓰지 않았다.
