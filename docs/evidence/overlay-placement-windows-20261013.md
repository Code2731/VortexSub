# UI-004 자막 창 자동 위치 복구 — Windows (2026-10-13)

## 구현

`OverlayPlacement.cs`에 순수 기하 계산을 추가했다.
화면 작업 영역과 위치는 물리 pixel, 창 크기는 DIP다.
현재 창과 가장 많이 겹치는 화면을 선택한다. 겹침이 없으면 기본 화면을 선택한다.
음수 원점과 서로 다른 배율을 처리한다. 작업 영역 안쪽 8 pixel 여백으로 위치를 제한한다.
창이 작업 영역보다 크면 크기와 최소 크기를 줄인다. 가능한 경우 현재 DIP 크기를 유지한다.
화면 목록이 비었거나 값이 유효하지 않으면 이동하지 않는다. 화면 목록 상한은 64개다.

`OverlayWindow`는 화면 목록·DPI·창 크기 변경을 구독한다.
표시할 때도 복구한다. 중복 알림은 UI dispatcher 작업 하나로 묶는다.
복구 시 폭 측정 cache를 비운다. 자막 본문·Run·줄 슬롯·읽기 lease는 변경하지 않는다.
숨긴 창은 이동하지 않는다. 종료 시 화면 목록 이벤트 구독을 해제한다.
기존 수동 위치 복구 버튼은 유지한다.

배율 0.75/1/1.25/1.5/2/3, 화면 폭 320/800/1920, 위치 5개를 조합했다.
작업 영역 안의 결과와 반복 알림의 동일 결과를 확인했다.

직접 후보와 실제 Deck/어댑터 오버레이에 복구 상황을 추가했다.
두 줄을 표시한 뒤 창을 화면 밖으로 이동했다. 실제 창 폭을 잠시 변경하고 원래 폭으로 복원했다.
native 크기 변경 알림→dispatcher→작업 영역 복구 경로가 동작했다.
복구 뒤 실제 Run 인스턴스와 읽기 lease가 같았다.
윗줄 2.5초·아랫줄 2.75초의 원래 만료와 고정 슬롯을 유지했다.
이 입력은 합성 자막과 가상 읽기 시계다. 실제 모니터 분리나 DPI 변경은 수행하지 않았다.

## 남은 범위와 인계

실제 모니터 분리·배율 변경·혼합 DPI 간 이동·macOS 알림/창 관리자 검증은 남았다.
아주 작은 작업 영역에서는 창 접근성만 기하적으로 확인했다. 두 줄 가독성은 별도 평가가 필요하다.
화면 제한 때문에 줄인 크기를 큰 화면에서 원래 사용자 크기로 자동 확대하는 기능은 추가하지 않았다.
현재 크기를 가능한 범위에서 유지한다. 사용자 크기 변경과 수동 위치 복구는 계속 사용할 수 있다.
실제 음성·새 모델 추론·OS 연속 프레임·실제 30분·Rust/IPC/전체 check는 이번에 실행하지 않았다.
새 읽기 정책이나 지연 개선으로 집계하지 않는다. 사용자 수동 재시험은 요청하지 않았다.
