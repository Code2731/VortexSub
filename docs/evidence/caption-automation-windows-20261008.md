# 자막 고정 입력 자동화 — Windows

2026-10-08. 사용자 요청은 반복 수동 테스트 부담을 줄이는 것이다.
브랜치 `master`, 기준 HEAD `15f1db0` 이후 작업 트리. 변경은 미커밋이다.

## 구현

`scripts/test-captions.ps1` 한 번으로 상태 검사·고정 입력 재생·실패 검출·저장 화면 비교를 실행한다.
공유 `CaptionRegression`은 상태 드라이버와 실제 오버레이에 같은 합성 입력을 보낸다.
개인 설정·worker·음성 캡처·추론 서버를 사용하지 않는다.
보고서는 실패 조건과 시각, 첫 줄 대기, 조기 삭제, 폐기 사유, 소스 해시를 담는다.
같은 입력의 이전 보고서와 비교한다. 출력 덮어쓰기와 결과 없는 통과를 막았다.

최근 읽기 보호 수정도 이 자동화로 실행 검증했다.
0.064초 원문 수정·반복 수정·교정·rollback·실패/중지·대기열 보존이 통과했다.
예전 정책을 적용한 별도 드라이버는 `reading_deadline` 실패를 냈다.
자동화가 임의 프로세스 오류를 정상적인 실패 검출로 인정하지 않도록 조건을 확인한다.

## 최종 실행

Windows / .NET SDK 10.0.102 / 기존 Python·Pillow와 복원된 .NET 패키지.
새 다운로드는 없었다. 결과 폴더의 시각은 UTC다. 한국 현지 실행일은 2026-10-08이다.

```powershell
& scripts/test-captions.ps1 -BaselineReport benchmarks/results/caption-regression-20261007T183624Z-00cf650e/report.json
```

가상 30분 세션은 상태 검사에서만 실행했다. 실제 30분 동안 앱을 관찰한 결과가 아니다.
조기 삭제 상황의 0.064초와 2.75초 PNG도 직접 열었다. 보호 중 두 줄 유지와 이후 교정 문장을 확인했다.
렌더 실행은 정상 종료했다. 실제 물리 화면의 연속 프레임을 검사한 것은 아니다.

첫 고정 입력 실행은 긴 꼬리 상황의 기대 시각 8.3초에서 실패했다.
0.1초 tick 경계로 아래 줄이 8.4초에 해제되는 실제 상태를 확인했다.
기대 시각을 8.4초로 고쳤다. 최종 문장 보존·읽기 기한·대기 상한 검사는 유지했다.
생산 자막 정책은 이번 자동화 구현 과정에서 변경하지 않았다.
