# 교정 문장 최초 표시 측정 — Windows (2026-10-10)

## 변경과 판정 범위

`scripts/caption_replay_timing.py`를 두 표시기 재생 비교에 연결했다.
합성 입력 6개 상황에 `timing_targets` 31개를 지정했다.
세션·epoch·발화·원문 revision·번역 request를 입력과 대조한다.
저장 프레임에서는 세션·epoch·발화·부분 단위 시작 위치와 정확한 문자열을 확인한다.
입력에 없거나 중복된 조각, 같은 버전의 충돌 본문, 잘못된 시각은 거부한다.

`newly_visible`은 입력 이후 처음 관측한 조각이다. 대기는 Done 입력부터 계산한다.
`already_visible`은 입력 직전 이미 보인 조각이다. 새 버전 표시로 집계하지 않는다.
`previously_delivered`는 앞서 보였다가 사라진 조각이다. 대기를 계산하지 않는다.
후속 버전이 먼저 도착하면 `superseded`다. 끝까지 관측하지 못하면 `not_visible`이다.
두 상태를 0초로 바꾸지 않는다. 문자열 내부 공백은 정규화하지 않는다.

이 측정은 문자열 전달 증거다. 화면의 Run이 특정 번역 request 소유라는 증거는 아니다.
문장 의미나 재사용 허가를 추측하지 않는다. 두 줄에 걸친 조각은 현재 측정하지 않는다.
기존 native 입력은 `timing_targets`가 없으면 이 지표를 생략한다.
제품의 표시 정책·읽기 시간·모델은 이번에 변경하지 않았다.

## 결과와 원인

두 표시기 모두 31개 중 새 조각 26개·이미 표시 3개·미표시 2개다.
미표시 2개는 기존 과부하의 3·4번 발화다. 허용 폐기 2건과 일치한다.

| 조각 또는 상황 | 입력 시각 | 첫 관측 시각: 기존 / 새 | 대기: 기존 / 새 |

| 뒤 문장 교정 `오른쪽 방향.` | 0.2초 | 2.8 / 2.8초 | 2.6 / 2.6초 |
| 앞문장 교정 `교정 앞문장.` | 0.1초 | 2.8 / 2.8초 | 2.7 / 2.7초 |

교정 문장의 첫 표시 대기는 줄어들지 않았다. 다음 발화의 개선과 구분한다.
장문의 1·2줄은 0초, 3·4줄은 2.8초, 5·6줄은 5.6초에 보였다.
이 입력의 대기는 추론 시간이 아니다. 두 줄을 읽는 동안 자리를 기다리는 시간이다.
교정은 해당 발화의 이전 읽기 lease가 끝날 때까지 `ReadingProtected`로 대기한다.
윗줄 기한은 2.5초다. 아랫줄은 0.25초 더 보호한다. 0.1초 Tick에서 다음 배정은 2.8초다.
`Display`의 교정 보호와 아랫줄이 남았을 때 윗줄 배정을 막는 조건을 소스에서 확인했다.

미상 원문의 종료 시각 증가 0.3초는 첫 교정 지연 증가가 아니다.
전체 교정 재표시와 아랫줄 읽기 기한이 종료 시각을 늘렸다.
이 상황의 같은 앞문장 최초 증거는 입력 전에 있다. 후속 재표시 횟수는 기존 횟수 검사로 판정한다.
