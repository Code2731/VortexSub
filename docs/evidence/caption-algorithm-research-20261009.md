# 실시간 번역 자막의 안정화·표시 알고리즘 조사

2026-10-09. 논문 본문과 연구자의 공식 구현·설명을 확인했다.
사용자 요청은 기존 설계에 필요한 알고리즘이 있는지 조사하는 것이다.
이번은 자료 조사와 계획 수정이다. 새 알고리즘의 실행 효과는 아직 측정하지 않았다.

## 결론

적용 후보가 있다. 우선 후보는 번역 결과의 LocalAgreement와 제한된 문장 조각 LCS 비교다.
줄 단위 표시 연구도 참고할 수 있다. 엔진 내부 정보가 필요한 AlignAtt4LLM은 별도 연구 후보다.
이 알고리즘들이 EchoSub의 두 줄·2.5초 정책에서 전체 지연을 해결했다는 증거는 없다.
제품 구현 전에 같은 입력의 정책 시뮬레이션을 진행한다.

## 1. 문제를 나눠서 판단한다

| 계층 | 결정 | 현재 상태 |
| --- | --- | --- |
| 전사 | 원문 중 어느 부분을 안정된 입력으로 볼 것인가 | 원문 LocalAgreement-2가 이미 있다 |
| 번역 | 새 번역 중 어느 부분을 다음 표시 후보로 보낼 것인가 | 전체 번역 후보와 변화 진단이 있다. 원문 guard는 번역의 안정성 보장이 아니다 |
| 표시 | 후보를 어떤 줄에 언제 배정하고 교정할 것인가 | prefix 재사용과 두 줄 보호가 있다. 교정은 전체 전환 대기를 만들 수 있다 |

원문 합의, 번역 합의, 줄의 읽기 보호는 서로 다른 상태다.
상위 계층의 빠른 출력을 하위 계층의 빠른 표시로 간주하지 않는다.

## 2. 알고리즘과 적용 판단

### A. 번역 LocalAgreement-2: 우선 시뮬레이션 후보

연속된 두 출력의 동일한 앞부분을 채택하고 남은 꼬리는 다음 갱신에서 비교한다.
SimulStreaming은 이 정책을 EuroLLM 번역에도 적용한다.
공식 출력 계약은 확정 출력과 수정 가능한 출력을 분리한다.
논문 구현은 채택한 번역 prefix를 후속 디코딩에 강제한다.
[CUNI IWSLT 2025 논문 §2·§4](https://aclanthology.org/2025.iwslt-1.41.pdf),
[공식 구현·출력 계약](https://github.com/ufal/SimulStreaming).

EchoSub에는 원문 합의가 있으나 같은 정책의 번역 확정 계약은 없다.
이미 도착하는 번역 후보를 비교하는 변형은 엔진 교체 없이 실험할 수 있다.
새 source revision의 후보와 같은 request의 중복 전달을 구분해야 한다.
문자 합의는 의미 정답이나 미래의 무수정 보장이 아니다.
최초 의미 단위 전체에 두 번째 번역 대기를 강제하면 현재 지연을 늘릴 수 있다.
따라서 최초 표시를 유지하고 미표시 꼬리에만 합의를 적용하는 변형을 별도 후보로 둔다.
이 변형을 논문 원형과 동일한 구현이라고 부르지 않는다.
최종 원문은 prefix 강제 없이 번역하고 필요한 교정을 허용한다.

### B. Mask-k와 이전 번역 편향: 안정화 근거가 있으나 지연을 함께 본다

Mask-k는 불완전한 입력의 번역 끝 k개 토큰을 숨긴다.
Biased search는 이전 출력의 토큰을 선호하도록 디코딩 분포를 조정한다.
기존 출력을 따라가다 처음 달라진 위치부터 편향을 해제한다.
[원 논문 §4](https://arxiv.org/html/1912.03393),
[후속 비교](https://aclanthology.org/2020.iwslt-1.27.pdf).

원 논문의 영어→독일어 TED 평가에서 baseline의 안정화 지연은 4.13초였다.
Mask만 적용한 구성은 5.98초였다. 편향과 mask를 결합한 구성은 4.11초였고,
normalized erasure는 2.11에서 0.12로 줄었다.
이는 해당 언어·모델·입력의 결과다. EchoSub의 속도나 한국어 결과로 환산하지 않는다.
[원 논문 표 2](https://arxiv.org/html/1912.03393).

끝부분을 잠시 보류하는 방식은 텍스트 trace로 비교할 수 있다.
LLM subword 토큰과 한국어 어절을 같은 단위로 취급하지 않는다.
어절·문장 경계를 쓰면 원형 mask-k와 다른 변형으로 기록한다.
현재 요청은 greedy·비스트리밍 chat completion이다.
논문의 편향은 UI 시간 조절이나 프롬프트 한 줄과 동일하지 않다.
원형을 재현하려면 디코딩 연동과 새 추론 출력 검증이 필요하다.

### C. LCS / Myers 차분: 표시 조립기의 우선 후보

Myers 알고리즘은 두 기호열의 최장 공통 부분 수열과 최소 편집 경로를 구한다.
기본 시간 복잡도는 O(ND)다. N은 두 입력 길이의 합, D는 편집 수다.
이 알고리즘은 문자열 차이를 구한다. 번역 의미를 판정하지 않는다.
[Myers 원 논문](https://neil.fraser.name/writing/diff/myers.pdf).

EchoSub 적용은 자체 설계다. 같은 원문 단위 안의 완결 문장 조각을 정확히 비교한다.
현재 앞 문장 prefix만 비교하는 방식에서, 뒤의 같은 문장을 재사용할 수 있는지 확인한다.
작은 제한 입력에는 문장 조각 LCS로 먼저 실험한다. Myers 채택은 비용 측정 후 결정한다.
보이는 줄을 차분 결과대로 즉시 삭제하거나 옮기지 않는다.
변경된 문장은 온전한 문장으로 교정한다. 서로 다른 문장의 단어를 섞지 않는다.
반복 문장·단위 변경·모호한 대응은 재사용하지 않는다.
짧아진 final에서 삭제된 주장도 교정해야 한다. 남은 동일 문장만 재사용하고 끝내면 실패다.

### D. 줄 분할과 줄 단위 표시: 원리를 참고한다

2021년 연구는 단어별 출력, 전체 block 출력, 줄 단위 스크롤을 비교했다.
모델이 자막 경계를 예측하고 각 줄의 경계가 나오면 표시하는 방식이다.
평가에는 표시 지연뿐 아니라 표시 시간당 글자 수가 포함된다.
[From Delay to Display §3](https://aclanthology.org/2021.mtsummit-asltrw.4.pdf).

이 논문은 영어→이탈리아어·독일어·프랑스어를 다룬다. 한국어 기준은 아니다.
제안된 스크롤은 줄을 위로 이동한다. 현재 사용자의 고정 위치 요구에 그대로 적용하지 않는다.
줄을 표시 작업 단위로 만들고 읽기 부담을 함께 측정하는 원리를 참고한다.
고정 두 줄의 순서와 읽기 기한을 적용하는 배정 정책은 EchoSub에서 따로 검증해야 한다.

### E. AlignAtt / AlignAtt4LLM: 엔진 연동이 필요한 후속 후보

2026년 AlignAtt4LLM은 decoder-only LLM에서도 attention 기반 출력 결정을 구현한다.
prompt의 원문 범위를 명시하고 언어별 attention head를 선택한다.
runtime에서 query/key를 수집해 번역 후보와 원문의 대응 정보를 계산한다.
논문은 Gemma-4와 vLLM 경로를 사용했다.
다른 모델에는 head와 채택 임계값의 재보정이 필요하다.
[AlignAtt4LLM 논문 §3~§5](https://aclanthology.org/2026.iwslt-1.32.pdf).

현재 EchoSub HTTP 계약은 번역 문자열을 받는다. 내부 attention 관측 경로는 없다.
따라서 이 정책은 표시기에서 설정 하나로 켜는 기능이 아니다.
Hy-MT2와 llama.cpp의 관측 연동, 추가 연산 비용, 한국어 보정 자료가 필요하다.
현재 모델에서의 지원·효과를 확인한 것으로 기록하지 않는다.

### F. Wait-k / 적응형 read-write 정책: 즉시 채택하지 않는다

DaP 연구는 미래 입력에 따른 분포 변화로 읽기·출력 결정을 한다.
이를 위해 frozen wait-k 모델에 추가 파라미터를 학습한다.
[Adaptive Policy with Wait-k Model](https://aclanthology.org/2023.emnlp-main.293.pdf).

EchoSub의 고정 대기 시간을 바꾸는 것만으로 이 연구를 재현할 수 없다.
현재 표시 대기의 첫 실험에는 학습 모델을 추가하지 않는다.

## 3. 앞선 설계에서 수정할 점

- 입력 계약 구현보다 같은 입력의 비교 시뮬레이션을 먼저 한다.
- 표시한 내용이라는 사실과 번역 합의로 채택했다는 사실을 구분한다.
- 같은 문장 재사용은 의미 분류가 아니라 제한된 차분 비교로 구현한다.
- 최초 의미 단위에 일괄 합의 대기를 추가하지 않는다.
- 논문의 스크롤과 고정 위치 줄 배정을 같은 정책이라고 표시하지 않는다.
- 편향·attention 정책은 출력 내용을 바꾼다. 기존 결과 trace 재배열만으로 검증할 수 없다.
- 미표시 꼬리·최종 교정·과부하를 함께 평가한다. 안정된 오역을 성공으로 인정하지 않는다.

## 4. 시뮬레이션 비교안

| 후보 | 변경 | 검증할 가설 |
| --- | --- | --- |
| S0 | 현재 생산 표시기 | 대조군 재현 |
| S1 | 표시 이력 분리 + 제한된 문장 LCS + 줄 단위 배정 | 동일 문장 재표시와 불필요한 전환 대기가 감소하는가 |
| S2 | S1 + 미표시 꼬리의 번역 합의 | 최초 표시를 유지하면서 반복 교정이 감소하는가 |
| S3 | S1 + 제한된 끝부분 보류 | 숨기는 내용과 추가 지연에 비해 안정성이 개선되는가 |

각 변경을 따로 비교한다. 모든 알고리즘을 한꺼번에 넣고 효과를 주장하지 않는다.
최초 결과 시각·최종 결과 시각·본문·식별자가 같은 trace를 사용한다.
현재 사용자 timing 로그는 본문이 없으므로 그 로그만으로 이 비교를 수행할 수 없다.
기존 고정 입력을 확장하고, 실제 모델 출력 trace는 별도 수집 단계로 구분한다.
중복 문장, 앞 문장 교정, 짧아진 final, 숫자·부정·조건 수정과 빠른 연속 발화를 포함한다.
결과를 튜닝한 입력과 채택 판단용 입력도 분리한다.
편향과 AlignAtt는 S0~S3 뒤에 실제 추론을 포함한 별도 비교로 둔다.

## 5. 평가 지표와 종료 기준

연구는 속도·정확도·불안정성을 함께 다룬다.
2023년 평가 연구는 첫 출력 대신 이후에도 유지되는 최초 출력의 지연을 측정한다.
분할과 구성 요소의 실행 시간도 포함한다.
[End-to-End Evaluation §5](https://aclanthology.org/2023.emnlp-demo.2.pdf).

EchoSub에서는 다음을 구분한다.

- 첫 줄 배정 대기와 최종 교정 배정 대기: 중앙값·P95·최대값, 단위는 초.
- 번역 후보의 erasure와 화면의 실제 변경: 후보 수정과 정상적인 줄 만료를 섞지 않는다.
- 같은 내용의 재표시 글자 수와 각 새 글자가 읽을 수 있었던 시간.
- 최종 교정 보존, 미표시 단위, 과부하 사유, stale 결과 적용.
- 자동으로 정답을 지정한 숫자·부정·조건 fixture의 교정 전달.

물리 화면의 깜빡임을 erasure 점수 하나로 판정하지 않는다.
그대로 잘못된 번역을 고정하거나 일부 발화를 생략해 지연을 줄인 후보는 탈락이다.
S1은 읽기 보호·교정·누락 회귀 없이 같은 trace의 대기와 중복 표시를 줄여야 한다.
S2/S3가 안정성만 개선하고 지연을 늘리면 그 교환을 별도로 보고한다.
지연 개선으로 채택할 때는 최초 의미 단위 P95가 악화하지 않아야 한다.
어느 후보도 통과하지 못하면 기존 정책을 유지하고 실패 원인을 기록한다.

## 확인 범위와 상태

공식 논문 본문, Google 연구 설명, SimulStreaming README 계약을 읽었다.
SimulStreaming의 개별 번역 소스 디렉터리/API 목록은 웹 도구로 충분히 열리지 않았다.
전체 저장소 실행·개별 함수 전수 검증은 수행하지 않았다.
현재 저장소의 Agreement, CaptionAssembly, 번역 HTTP 계약과 P2 계획을 대조했다.
새 라이브 실행·모델 다운로드·정책 시뮬레이션·자막 테스트는 이번에 하지 않았다.
기존 자막 코드와 개인 설정은 변경하지 않았다. 사용자 수동 재시험도 요청하지 않았다.
브랜치 `master`, 기준 HEAD `15f1db0`. 문서는 미커밋이며 다른 PC에 전달되지 않았다.
