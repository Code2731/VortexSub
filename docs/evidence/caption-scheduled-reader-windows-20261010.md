# 후보 줄 배정기·오버레이 Windows 검증

검증일: 2026-10-10, Asia/Seoul. 결과 폴더의 날짜는 UTC다.
브랜치 `master`, 기준 HEAD `15f1db0`. 이번 변경과 이전 작업은 미커밋이다.
커밋·푸시·다른 PC 전달은 하지 않았다.

## 구현과 범위

`CaptionScheduledLines`가 저장소·읽기 보호·문장 재사용 증거를 소비한다.
열린 줄 append, 고정 두 슬롯, 빈 아랫줄 배정과 기한 만료를 구현했다.
교정 앞문장을 표시한 뒤 같은 뒷문장은 검증된 재사용으로 처리한다.
새 교정의 윗줄이 같은 버전의 아랫줄을 막지 않도록 저장소의 이전 버전 가드를 보강했다.
separator append는 읽기 기한을 유지한다. 일반 글자는 이 예외를 사용할 수 없다.
선행 CRLF는 빈 슬롯 없이 소비하고 별도 전달 이력으로 남긴다.
한 Tick은 최대 8단계다. 작업이 남으면 다음 Tick으로 넘긴다.

실제 `OverlayWindow`의 진단 경로에서 같은 줄 컨트롤·폭 측정·Run 렌더를 사용했다.
진단 입력과 기존 `SetCards`의 혼용은 거부한다.
기본 live/mock 실행 경로는 기존 표시기를 유지한다. worker/deck 어댑터는 이번에 연결하지 않았다.
새 배정기의 실제 모델·음성 지연 개선 결과로 해석하지 않는다.

## 실행과 결과

구현 전에 기존 회귀를 실행했다.
첫 실행은 요약기 임시 파일 접근 권한으로 실패했다. 같은 검사를 권한이 허용된 환경에서 재실행해 통과했다.
앱 동작 실패로 집계하지 않는다. 구현 후 새 배정기와 후보 화면 검사를 통합했다.
최종 명령은 저장소 루트 기준이다.

```powershell
& scripts/test-captions.ps1 -BaselineReport benchmarks/results/caption-regression-20261009T162248Z-e578ddb7/report.json
```

전체 결과·로그·PNG는 Git 제외다.

## 확인한 동작

- 읽기 기한 전에는 교정 입력으로 기존 줄을 지우지 않는다.
- 교정 뒤 같은 뒷문장을 두 번 배정하지 않는다. 다음 발화는 빈 아랫줄에 배정한다.
- 한 줄 만료 뒤 남은 아랫줄은 위치를 유지한다.
- 열린 줄 성장 시 기존 Run과 기존 글자 픽셀이 유지된다.
- 개행 append는 글자나 읽기 기한을 변경하지 않는다.
- 원문 수정은 표시 줄을 유지한다. 명시적 철회·중지는 지우고 다시 표시하지 않는다.
- 긴 교정은 새 버전의 두 슬롯에 배정한다.
- 부분 단위에서 전체 final로 복원해도 다른 발화의 대기 final 4개는 유지한다.
- 숫자·부정·미상 범위·퇴역 증거의 기존 재사용 검사도 재통과했다.

새 배정기의 가상 300개 발화 교정·재사용을 1,800초 동안 반복했다.
교정 전 보호, 교정 앞문장 배정, 한 번의 재사용, 슬롯 만료와 전체 저장 상한을 검사했다.
기존 계약의 가상 장시간 검사와 구분한다. 실제 30분 음성 검사는 아니다.
후보 스냅샷 중 교정 윗줄·다음 발화 아랫줄 화면도 직접 확인했다.

## 환경과 잔여

Windows 11 Home x64 / Ryzen 7 5800X / RTX 3080 / .NET SDK `10.0.102`.
기존 Python/Pillow와 복원한 패키지를 사용했다. GPU 추론은 실행하지 않았다.
새 모델·런타임·의존성 다운로드와 개인 설정 변경은 없다.
모델·캐시·로그·화면이 다른 PC로 전달된다고 가정하지 않는다.

미검증: 기본 worker/deck 입력 연결, 실제 음성·모델 추론·일반 의미 품질,
OS 연속 프레임·실제 30분 gate·macOS·UI 스레드 비용과 실제 프로세스 메모리.
Rust·IPC·전체 check 스크립트는 이번에 실행하지 않았다. 해당 소스는 변경하지 않았다.
수동 재시험은 요청하지 않았다.
