# 같은 뒷문장을 유지한 앞문장 교정 — Windows (2026-10-10)

## 구현과 허용 조건

`CaptionScheduleStore.CanDisplayAboveRetainedLower`를 추가했다.
읽기를 마친 윗줄에 교정 앞부분을 배정한다. 읽는 아랫줄은 그대로 유지한다.
기본 live의 `CaptionScheduledLines`와 기록 어댑터에 적용된다.

다음 조건을 모두 요구한다.

- 현재 교정 토큰과 배정 순서가 일치한다. 교정 사유는 `TargetChanged`다.
- 원문 범위와 revision이 같다. `SameSourceSentences` 증거를 다시 검증한다.
- 윗줄 lease는 만료됐다. 아랫줄은 같은 발화·부분 단위의 이전 버전이다.
- 아랫줄 전체가 증거의 닫힌 문장 범위와 정확히 같다.
- 교정 앞부분 전체가 한 줄에 들어간다. 배정 끝은 같은 뒷문장 시작과 일치한다.

Store는 조회 결과만 믿지 않는다. 실제 `Display`에서 토큰·해시·범위·lease를 다시 확인한다.
잘못된 증거와 일반 호출은 기존 `ReadingProtected`·`AppendOrder` 가드를 유지한다.
원문 변경·범위 미상·변경된 꼬리·열린 꼬리·한 줄을 넘는 앞부분에는 적용하지 않는다.
아랫줄의 Run·슬롯·기한은 변경하지 않는다. 새 윗줄은 최소 2.5초 보호한다.
새 아랫줄의 배정은 기존 읽기 시간과 stagger를 따른다.
이전 아랫줄에는 기한 연장을 적용하지 않는다.
진단은 `FirstLine.reason = RetainedLowerCorrection`이다. 본문 로그를 추가하지 않았다.
