# 사용자 자막 로그와 미완성 영어 보류 (2026-10-01)

## 사용자 실행 관측

사용자가 옵션을 켜고 실행한 로그를 읽었다. 이번 라운드에서 캡처를 실행하지 않았다.
런처 기록은 Windows CUDA/빠른 부분 모드다. Git 제외 원본:

- `logs/caption-timing-20261001-225153-785fa4b969f843b7bbb123e0cfc802ca.jsonl`
- `logs/translation-20261001-225126-15608.stderr.log`

`scripts/summarize-caption-timing.py <위 caption 로그>` 결과:

| 구간 | 개수 | 중앙값(초) | 최소(초) | 최대(초) |
|---|---:|---:|---:|---:|
| 번역 이벤트 수신→첫 visible Deck 반영 | 32 | 0.033161 | 0.002015 | 0.036089 |
| Deck 보호로 보류한 시간 | 32 | 0 | 0 | 0 |
| 서버 total time | 32 | 0.287265 | 0.129620 | 1.047940 |

누락 receipt/보고된 drop/잘못된 행은 모두 0이다. Deck 반영 이후 다음
오버레이 속성 대입의 중앙값은 0.000032초, 최대 0.003955초다.
서버 통계는 같은 실행 파일의 32개 처리 기록 집계이며 요청 ID별 연결이 아니다.
서버 total은 prompt eval+eval이며 HTTP 전체/음성→자막 지연이 아니다.
속성 대입은 실제 화면 렌더 완료가 아니다. 비교 대조 실행이 없어 개선율을 계산하지 않는다.
이 관측에서는 UI 반영 대기가 작다. 음성 수집·ASR·안정 판별·번역 대기 중
어디가 전체 지연의 주원인인지는 이 로그로 구분하지 못한다.

## 구현과 확인 범위

영어 임시 단위에 숫자/관사 끝, 미완성 조건 조각과 최신 전사의 조건 시작을
보류하는 규칙을 추가했다. 확정 번역 경로와 기본 꺼짐은 유지한다.
[규칙·부작용](../TRANSLATION_UNITS.md)을 따른다. 기존 fixture 중 관사로 끝난
수정 원문은 요청 없음으로 기대값을 바꾸고, HTTP 예약 fixture는 조건 시작이
없는 연속 원문을 사용하도록 조정했다. 새로운 테스트는 추가하지 않았다.

Windows 기본 worker 빌드, native CUDA/VAD release worker 빌드,
`cargo fmt --all -- --check`, `git diff --check` PASS.
이번 변경의 테스트 실행·실제 HTTP 품질 비교·사용자 UI 재실행·게임·macOS는
미실행이다. 앞의 사용자 측정은 이번 보류 규칙 적용 전 버전이다.
