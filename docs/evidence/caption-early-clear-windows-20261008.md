## 확인한 삭제 경로

원본 로그에는 `InvalidatedVisible/SourceInvalidated`가 45건 있다. 25개 segment에 걸친 줄 단위 관측이다.
`CaptionDeck.ObserveOrdered`는 표시 원문의 prefix와 새 원문이 다르면 구간을 무효화한다.
`CaptionLines.Apply`는 이를 `clearVisible: true`로 처리한다.
따라서 2.5초 읽기 보호가 끝나기 전에도 표시 줄을 지운다.
이 판정은 문자열 prefix 불일치다. 의미 반박 여부를 판단한 결과가 아니다.

직전 두 수정만으로 읽기 문제가 해결됐다고 볼 수 없다.

## 진단 보완과 한계

기존 요약기는 `InvalidatedVisible`과 `SeparatorConsumed`를 집계 대상에서 빠뜨렸다.
두 항목을 허용 목록에 추가했다. 이번 로그 재분석에서 표시 줄 삭제 45건이 집계된다.

```powershell
python scripts/summarize-caption-timing.py logs/caption-timing-20261008-030633-37992.jsonl
```

종료 코드 0. 산출물은 Git 제외 `benchmarks/results/user-reading-20261008-030633-summary.json`이다.
입력 오류와 보고된 로그 유실은 0이다. 수신/적용 매핑의 상한 퇴역은 97건이다.
첫 줄·대기 구간 표본 퇴역은 0이다. 매핑 퇴역을 로그 유실이나 모든 통계의 무손실로 해석하지 않는다.
새 앱 실행·빌드·자동 테스트·화면 촬영은 수행하지 않았다. 의미 품질과 30분 검증은 미완료다.

## 다음 수정

원문 prefix 수정 시 미표시 입력·대기 수정본은 폐기하되 이미 읽는 줄은 기존 기한까지 유지한다.
새 원문에 맞는 번역을 다음 배정에 사용한다. 반복 수정으로 기존 읽기 기한을 연장하지 않는다.
중지·세션 변경과 실패/폐기의 처리를 구분한다. 수정 대기와 조기 삭제를 함께 검사해야 한다.
