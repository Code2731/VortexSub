# 자막 표시 입력 계약 검증

2026-10-09, Windows x64. [정책 비교](caption-policy-simulation-windows-20261009.md)의 다음 단계다.

## 이번 변경

`CaptionScheduleStore`와 입력·원문 범위·토큰·표시 이력·교정 후보·읽기 보호 계약을 구현했다.
Desktop에서 빌드하고 검사 프로젝트에 같은 소스를 연결했다.
현재 `CaptionLines`와 오버레이는 새 저장소를 호출하지 않는다.
제품의 표시 방식과 개인 설정은 이번 라운드에서 변경하지 않았다.

원문 단위는 UTF-16 시작/끝 위치와 기준 revision을 함께 담는다.
범위가 없는 이전 기록과 서로 다른 revision의 범위는 미상으로 분류한다.
문자 길이만으로 원문 suffix나 번역 위치를 추정하지 않는다.
`FromRecord`는 완료·적용 revision·원문 suffix와 문자소 경계를 검증한다.
원문 prefix보다 긴 단위는 뺄셈 전에 거부한다.

표시 이력은 입력 교체 뒤에도 유지한다. 원문 수정은 미표시 입력만 취소한다.
읽기 중인 줄을 저장 압력으로 지우지 않는다. 명시적 중지·세션 초기화·최종 철회는 별도 경로다.
단위마다 최신 미표시 입력 하나를 보관한다. stale 토큰으로 표시하거나 완료할 수 없다.
실제로 배정하지 않은 내용을 `Complete`로 처리할 수 없다.

상한은 본문 16,384, 저장 본문 합계 131,072 UTF-16 단위다.
단위 64개, 대기 4개 외 현재 작업 1개, 표시 이력 전체 256개/단위별 64개다.
알림은 본문과 내부 저널을 보관하지 않는다. 카운터 키 개수도 제한한다.
문자 예산은 최신/이력 문자열 payload다. 객체·메타데이터·외부 복사본의 전체 메모리 측정은 아니다.

입력 수용 전에 퇴역·이력 축소·큐 교체를 예약 검사한다.
저장 실패는 기존 미표시 입력과 보호 줄을 유지한다.
가장 오래된 segment의 전체 단위 그룹만 퇴역한다. 살아 있는 앞 구간을 건너뛰지 않는다.
읽은 이력을 줄이면 `HistoryComplete = false`를 기록한다.
이 상태에서 전체 LCS 대응을 입증한 것으로 처리하지 않는다.

## 중요 경계 검사

검사 전용 `CaptionScheduleContractSmoke.cs`를 추가했다.
`scripts/test-captions.ps1`에 `input-contract-checks`를 연결했다.

- 세션 미시작·이전 context·NaN·시각 역전·잘못된 입력·최대 입력.
- 오래된 revision/request, 같은 버전의 충돌, final 뒤 preview, 취소 버전 재진입.
- 원문 범위 미상, 범위 중첩/비중첩, Unicode surrogate/ZWJ/결합 문자 경계.
- 입력 교체 뒤 불변 snapshot, stale 토큰, 미표시 완료 거부.
- 두 줄 읽기 보호, 만료 간격, append, 미표시 꼬리 교체와 실제 범위 완료.
- 원문 반복 수정 뒤 고정 읽기 기한, 명시적 철회와 세션 재시작의 토큰 무효화.
- 전체 final이 현재 부분 작업을 인계할 때 다른 발화의 final 4개 보존.
- 이전 원문 단위의 완료 범위로 겹치는 최종 교정을 완료 처리하지 못하도록 차단.
- 큐 용량·10초 경계·최대 단위·실패 예약의 기존 상태 보존·그룹 퇴역.
- 최대 본문 연속 입력, 단위별/전체 이력 제한, 600문장의 가상 30분 상태.

읽기 보호·원문 수정·큐 교체를 서로 다른 동작으로 검사했다.
초기 검사에서 이력의 단위 상한과 전체 상한을 각각 충족하며 한 조각을 더 버리는 동작을 찾았다.
단위 상한을 먼저 맞춘 뒤 전체 상한을 맞추도록 수정했다.
전체 final이 현재 부분 입력을 대체하는 경우에는 현재 작업 자리를 인계하도록 보강했다.
이 인계가 새 대기 입력 하나로 집계되어 다른 발화를 버리지 않도록 했다.
같은 버전의 오래된 입력은 final 회귀보다 stale 사유를 먼저 반환하도록 정리했다.

## 실행과 결과

기존 회귀를 먼저 실행했다. 이어 계약 검사를 개발하고 전체 회귀에 연결했다.
저장소 루트의 최종 명령은 다음과 같다.

```powershell
& scripts/test-captions.ps1 -BaselineReport benchmarks/results/caption-regression-20261009T115254Z-b8d5e714/report.json
```

최종 결과 폴더는 `benchmarks/results/caption-regression-20261009T123317Z-0bacd1de/`다.

| 기존 상태 검사 | 189개 통과 |
| 고정 입력 상태 | 16개 상황 / 20,432 검사 통과 |
| 기존 고장 대조군 | 예전 조기 삭제 실패 검출 |
| 타이밍 요약기 | 10개 통과 |
| 기존 Avalonia 렌더 | 15개 상황 / 1,227 검사 통과 |
| 저장 화면 | PNG 85개 / 픽셀 398개 통과 |

`contract.json`에 상황별 검사와 제외 범위를 기록했다.
`report.json`에는 새 계약 소스·검사 소스의 SHA-256과 실행 단계가 포함된다.
동일 보고서 경로를 다시 전달했을 때 예상 종료 코드 2로 거부했다.
거부 전후 보고서 SHA-256이 같았다. `overwrite-check.json`에 결과를 저장했다.

Windows x64와 .NET SDK `10.0.102`에서 실행했다.
기존 Python/Pillow와 복원한 패키지를 사용했다. 새 모델·런타임·의존성을 내려받지 않았다.

## 미검증과 다음 작업

이번 렌더 검사는 기존 제품 표시기의 검사다. 새 저장소는 실제 화면에 연결하지 않았다.
후보 LCS·줄 배정·화면, 자연 음성·모델 추론·일반 의미 품질·OS 연속 프레임·macOS는 미검증이다.
600문장의 상태 검사는 실제 30분 재생이나 음성 검증이 아니다.
저장 문자열 예산은 프로세스의 실제 RSS/GC 상한 측정이 아니다.
사용자 수동 재시험은 요청하지 않았다.

다음은 제한된 문장 조각 비교와 재사용 증거를 구현한다.
미상/중첩/불완전 이력에는 전체 교정을 남긴다. 숫자·부정 표현의 의미 동등성은 추측하지 않는다.
이후 현재 열린 줄 append와 고정 슬롯 정책을 보존하면서 배정기를 연결한다.
제품 연결 후 상태·렌더 회귀와 후보 화면 검사를 먼저 실행한다.
계약과 호출 규칙은 [입력 계약](../CAPTION_INPUT_CONTRACT.md)을 따른다.

브랜치 `master`, HEAD `15f1db0`. 이번 소스·검사·문서는 미커밋이다.
푸시·파일 전달은 하지 않았다. 다른 PC에서 최신 작업을 바로 재개할 수 있다고 표시하지 않는다.
모델·로그·결과·화면·캐시는 Git 제외다. 실제 캡처 시작 원인 조사는 계속 보류한다.
