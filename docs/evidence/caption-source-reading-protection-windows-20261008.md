# 원문 수정 시 표시 줄 읽기 보호

2026-10-08. 브랜치 `master`, 기준 HEAD `15f1db0` 이후 로컬 변경.
[사용자 재시험](caption-early-clear-windows-20261008.md)에서 원문 prefix 수정이 읽기 보호를
우회해 표시 줄을 지우는 경로를 확인했다. 이번에는 그 경로를 수정했다.

## 변경

- `CaptionDeck`의 `RevisedSegments`와 `InvalidatedSegments`를 분리했다.
  원문 prefix 수정과 아직 사용할 수 없는 원문은 전자로 전달한다.
  Failed/Discarded/Skipped는 후자로 전달한다. 두 목록은 매 전달 후 비운다.
- 원문 수정은 해당 구간의 미표시 입력·대기 수정본을 폐기한다.
  이미 표시한 줄은 현재 위치와 기존 만료 시각을 유지한다.
  원문 수정이 반복돼도 만료 시각을 갱신하지 않는다.
- 표시 줄마다 수정된 원문에 속하는지 표시한다. 상태 공간은 두 줄로 고정했다.
  수정된 원문의 번역을 기존 열린 줄에 붙이지 않는다.
  같은 구간의 새 단위도 기존 줄의 읽기가 끝나기 전에 빈 아랫줄로 우회하지 않는다.
- 다음 유효 번역은 기존 교정 경로로 넘긴다. 그대로인 앞 문장은 기존 재사용 규칙을 따른다.
  다른 구간은 기존 대기열 순서를 따른다. 두 줄 위치와 2.5초 보호 시간은 유지한다.
- 실패/폐기는 해당 줄을 지운다. 중지·세션 변경은 기존 초기화 경로를 유지한다.
- `ReadingRetained/SourceRevised`를 추가했다. 같은 표시 줄의 반복 수정은 중복 집계하지 않는다.
  이미 만료된 줄에는 보호 관측을 기록하지 않는다. 요약기에도 집계를 추가했다.

2026-10-05의 “원문 철회 즉시 표시 삭제” 정책 중 일반 원문 수정 부분을 대체한다.
수정된 원문의 이전 번역이 기존 읽기 기한까지 잠시 남을 수 있다.
이는 의미 정확성 판정이 아니다. prefix 불일치를 의미 반박으로 단정하지 않는다.

## 확인 범위

표시 계약 사용처와 초기화·만료·대기열 입장·교정 경로를 코드로 대조했다.
기존 rollback 검사의 기대값을 새 정책에 맞췄다. 새 검사는 추가하지 않았다.

저장소 루트에서 기존 .NET SDK와 복원된 패키지로 빌드했다.

```powershell
$env:NUGET_PACKAGES = Join-Path $PWD '.nuget/packages'
$env:AVALONIA_TELEMETRY_OPTOUT = '1'
dotnet build apps/EchoSub.Desktop/EchoSub.Desktop.csproj --no-restore
dotnet build tests/EchoSub.ProtocolSmoke/EchoSub.ProtocolSmoke.csproj --no-restore
```

두 빌드 모두 종료 코드 0, 경고 0 / 오류 0.
자동 테스트는 실행하지 않았다. 이전 라운드의 189개 통과를 이번 변경의 결과로 사용하지 않는다.
실제 음성·모델 추론·물리 화면·30분 사용·macOS도 이번에 검증하지 않았다.
사용자 체감 개선과 지연 감소는 아직 확인하지 않았다.

## 다음 작업과 전달

반복 원문 수정·단위 rollback·같은 prefix의 새 번역에서 줄 유지와 교정 전환을 실행 검증한다.
실패/중지의 삭제와 다른 구간의 대기열 보존도 함께 확인한다.
그다음 실제 세션의 조기 삭제와 읽기 대기를 함께 비교한다.
요약의 `ReadingRetained`는 물리 화면의 읽기 시간을 증명하지 않는다.

새 모델·런타임 다운로드나 개인 설정 변경은 없다. 로그·모델·캐시는 Git 제외다.
변경은 미커밋이며 푸시하지 않았다. 다른 PC에서 재개하려면 소스를 먼저 전달해야 한다.
